# 筆追従局所更新・ローカル検証記録

## 記録範囲

- 日付: 2026-08-20（Asia/Tokyo）
- アプリケーション版: 0.7.1
- 基線: `6eb283c391f2d78e4542c2b1058759ae5f0fcac4`（版0.7.0）
- 環境: macOS Darwin 25.5.0 arm64、Apple M4、Python 3.11.15、PySide6 6.11.1
- 測定方式: `QT_QPA_PLATFORM=offscreen`。Windows実機、実マウス、実モニターの
  入力対光子測定ではない。

この記録は、筆入力一件ごとの全寸法mask確保、全ラベルRGB・`QImage`再生成、Canvas全体更新要求を
局所化した版0.7.1の実装証拠である。ラベル値域検証と完成表示像の再構築は全寸法処理を残す。
Windows配布候補の性能受理、対象業務PCでの50ms目標、人間による追従感の受理は閉じない。

## 変更した処理境界

版0.7.0では、各マウス移動について画像全寸法の真偽値mask、全ラベルからのRGB配列、所有
`QImage`を作り直し、Canvas全体の更新を要求していた。版0.7.1では次へ変更した。

1. `paint_brush_increment`は、離散筆とBresenham線分の外接矩形を画像範囲と保護領域へ
   切り詰め、そのROI内だけにmaskを確保する。
2. 実際に異なるラベルへ変わった時だけ半開矩形`(left, top, right, bottom)`を返す。同色の
   上を再度なぞった時と、編集可能範囲外だけの区間は`None`を返す。
3. `ImageCanvas.refresh_label_region`は返却矩形だけを現在の保存色または疑似色でRGB化し、
   既存ラベル`QImage`へ反映する。
4. 完成表示像は局所更新後のラベル像から原解像度で作り直す。比較不透明度を増分累積せず、
   保存元も従来どおりラベル配列だけとする。
5. 画面更新は筆変更矩形と旧・新ポインタの別々の矩形だけを要求する。Qtが非連続の
   `paintEvent`領域を渡した時も、背景と格子をその構成矩形ごとに列挙する。
6. Undo、Redo、取消、色表、可視性、不透明度などの全体変更には従来の全画像更新を残す。
7. 三値画像上では筆・塗り潰し・保護の独自表示へ位置指示を一本化し、OSカーソルを隠す。
   画像外は通常表示、`Space`一時移動と中ボタン移動は手形を維持する。

2048×1536、径5、短い一区間の公開構造試験では、演算用maskの確保形状は従来相当の
`(1536, 2048)`から`(9, 13)`へ縮小した。これは処理方式の証拠であり、それ単独で画面追従時間を
証明しない。

## 自動試験

```text
QT_QPA_PLATFORM=offscreen uv run --locked pytest -q
477 passed in 4.79s

QT_QPA_PLATFORM=offscreen uv run --locked pytest -q \
  $(git ls-files 'tests/test_*.py') tests/test_brush_responsiveness_contract.py
115 passed in 1.82s

QT_QPA_PLATFORM=offscreen uv run --locked pytest -q -m performance \
  tests/test_brush_responsiveness_contract.py
1 passed, 14 deselected in 0.40s
```

公開`tests/test_brush_responsiveness_contract.py`は次を固定する。

- 円・正方形、偶数径、画像外通過・再進入を含む全筆跡参照との最終画素一致。
- 変更矩形が全変更画素を含むこと、同色・保護領域では`None`になること。
- 2048×1536の短区間で全画像maskを確保しないこと。
- 保存色、疑似色、比較（明）、比較（暗）、不透明度における局所更新と全再構築の画素一致。
- 主画面の筆previewが局所更新を使い、無変更時は画像更新を呼ばないこと。
- 疎なポインタ移動が旧・新位置を別々の小矩形で更新し、全画面・外接帯更新を要求しないこと。
- 非連続`paintEvent`領域を外接矩形へ潰さず、高倍率格子を各構成矩形へ限定すること。
- 筆・塗り潰し・保護ではOSカーソルを隠し、画像外、表示切替、一時・実パンで適切に戻すこと。
- 同一process内で、局所筆経路の中央値が全画像更新経路の50%未満であること。

性能試験の50%は機種共通の絶対性能要求ではない。同じ実装・同じprocess内で全画像更新へ
退行したことを検知する広い相対門である。

## 互換・依存・安全面

- `pyproject.toml`と`uv.lock`の依存package名・版範囲は変更していない。変更は本応用版の
  `0.7.0`から`0.7.1`への同期だけであり、`uv lock --check`が成功した。
- CLI入口、画像入力形式、保存PNG、設定schema、履歴・未保存判定、保存先、外部lock規約は
  変更していない。`paint_brush_increment`は従来の配列変更作用を維持し、追加で変更矩形または
  `None`を返す。戻り値を捨てる既存呼出しはそのまま動く。
- アプリ本体に新しい認証、認可、秘密情報、環境変数契約、network通信、telemetry、外部log、
  永続書込先を追加していない。追加した実行時状態は、既存ラベル配列、表示用`QImage`、Qt更新矩形に閉じる。
- 公開四試験、全試験、Ruff、固定lock、sdist/wheel構築、画面外GUI煙試験を再実行した。
  これは変更面の局所互換証拠であり、第三者が未文書のPython内部関数を直接利用する場合まで
  公開APIとして保証するものではない。

## 代表寸法A/B観測

2048×1536、径5、長さ約9画素、1200×800 Canvas、原画像重畳ありについて、ポインタ更新、
筆演算、ラベル表示更新、完成表示再構築、Qt event処理を一回分として反復した。

収載した`scripts/benchmark_brush_responsiveness.py`を次の命令で実行した。100%は64反復、
800%は44反復で、各先頭4件を暖機として除外し、p95はnearest-rankで算出する。原出力は
`docs/brush-responsiveness-benchmark-2026-08-20.json`に保存した。

```text
QT_QPA_PLATFORM=offscreen uv run --locked python scripts/benchmark_brush_responsiveness.py
```

| 表示状態 | 経路 | p50 | p95 | 最大 | p50比較 |
| --- | --- | ---: | ---: | ---: | ---: |
| 100%・格子なし | 全画像更新相当 | 18.250 ms | 19.369 ms | 20.501 ms | 1.00倍 |
| 100%・格子なし | 局所更新 | 1.466 ms | 1.497 ms | 1.584 ms | 12.45倍 |
| 800%・格子あり | 全画像更新相当 | 32.200 ms | 32.471 ms | 32.623 ms | 1.00倍 |
| 800%・格子あり | 局所更新 | 1.610 ms | 1.720 ms | 1.755 ms | 20.00倍 |

同条件のp50処理時間は、格子なしで92.0%、格子ありで95.0%減少した。ここでいう
「全画像更新相当」は版0.7.1のROI筆演算へ旧`refresh_labels`を接続した同一process比較であり、
版0.7.0の全mask確保まで完全再現した値ではない。改修前に別probeで観測した同寸法・径5の
一移動処理はp50 19.469ms、p95 19.777msだったが、同一process A/Bではないため参考値とする。

## 未完了境界

- Windows 10 / 11の配布候補、対象業務PC、実マウス、タッチパッド、高DPI、実モニターは未測定。
- Qt event受領から`paintEvent`完了までの局所値を、実入力から画面画素変化までの時間へ
  読み替えない。Windowsでは高速度撮影または同等の外部観測が必要である。
- 最大径、極端に長い画像外線分、4K級画像、長時間連続筆跡のp95/p99と待ち行列年齢は未測定。
- 筆解放時の履歴差分生成は全配列比較を残すため、移動中の追従とは別に解放時の引っ掛かりが
  残る可能性がある。
- 最終的な追従感、曲線と鋭角、停止後の追越し、解放後tail、疲労は利用者がWindows判断門で
  `accept / reject / hold`を決める。
