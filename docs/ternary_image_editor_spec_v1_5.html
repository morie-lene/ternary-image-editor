1. 目的・適用範囲

1.1 製品目的

同一対象に対応する原画像と三値画像を画素座標が一致した状態で重畳表示し、利用者が原画像を参照しながら三値画像のみを修正し、修正版を別フォルダへ保存できるようにする。

OBJ-001
誤りの最終判断は利用者が目視で行う。ツールは正解画像を推論せず、比較・編集・規則処理を支援する。
OBJ-002
原画像は常に読取専用とし、編集・Undo・Redo・保存の対象にしない。
OBJ-003
入力三値画像を上書きせず、編集済み画像を専用出力フォルダへ明示保存する。

1.2 初期版で扱う範囲

  • 複数の画像対の読込、対応付け、自然順整列、前後移動。
  • 原画像と三値画像の重畳比較、疑似色表示、原画像不透明度変更。
  • 筆・塗り潰しによる三値画像編集。
  • 編集用の選択色を直接指定し、または三値間で順方向・逆方向に循環切替する。
  • Undo・Redo。
  • 二種類の自動境界生成。
  • 50画素以下の独立成分の強調表示。
  • 別フォルダへの検証付き保存。
  • 三値画像の下端100画素を読込時・保存時に「無」へ強制し、作業中も保護する。
  • 主画面の単発・刻み・保持操作に対するキー割当を、設定画面から変更・解除・初期化する。
  • 変更不要の画像も明示保存でき、出力ファイルの存在を作業済みの運用上の目印として利用できる。
  • 表示・編集の初期値、疑似色、および主画面操作のキー割当を設定画面から変更・永続化できる。

2. 用語と画素規則

用語定義
原画像比較対象となる無加工の画像。ファイル名は原則として ① または ② で始まる。
三値画像#000000、#808080、#FFFFFF の三値だけで構成される編集対象画像。ファイル名は 001 または 002 で始まる。
編集済み画像出力フォルダに保存された三値画像の修正版。
無黒 #000000。内部ラベル値 0。
有灰 #808080。内部ラベル値 1。
境界白 #FFFFFF。内部ラベル値 2。
選択ラベル筆および塗り潰しが次に書き込む意味値。「無」「有」「境界」のいずれか一つ。表示用疑似色ではなく内部ラベル値で管理する。
四近傍対象画素の上・下・左・右。斜めは含まない。
八近傍四近傍に斜め四方向を加えた八方向。
自然順整列数字列を数値として比較し、1, 2, 10 の順に並べる方式。
下端保護領域三値画像の座標 0 ≤ x ≤ 2047、1436 ≤ y ≤ 1535 に当たる下端100行。常に「無」#000000 とし、利用者操作による変更を許可しない。
操作ID保存、Undo、表示切替等の操作を設定値や表示名から独立して識別する不変の識別子。例：file.save。
キー組合せCtrl、Alt、Shiftの修飾キー0個以上と、修飾キー以外の主キー1個を同時に押す一段の入力。複数段の連続入力は含まない。
キー入力待機状態設定画面が通常の操作実行を停止し、次に入力された有効なキー組合せを割当候補として取得する状態。
基準配列未保存判定の比較対象。読込時は検証済み画像を下端強制無化する直前のラベル配列、正常保存後は保存した正規化済みラベル配列とする。
未保存状態現在のラベル配列と基準配列の内容が一画素以上異なる状態。履歴上の位置だけでは判定しない。
出力あり対応する出力ファイルが存在する状態。変更不要画像を明示保存した場合も含む。初期版では別個の「確認済み」管理情報を持たない。
操作型操作の発火方式。「単発」は一押下で一度実行、「刻み」は一入力ごとに規定量を変更し自動反復可、「保持」はキー押下中だけ状態を有効にする。
論理キーWindowsおよびQtが解釈したキー意味と修飾キーの組合せ。物理走査符号や鍵盤上の位置そのものではない。
規則の使い分け：塗り潰しと境界生成は誤変更を抑えるため四近傍、小領域検出は斜めに連なる塊を見逃さないため八近傍を使う。美観のために近傍規則を統一してはならない。

3. 入出力データ

3.1 共通条件

DAT-001
原画像・三値画像はともに 2048 × 1536ピクセルであること。
DAT-002
画像対は回転、反転、切抜き、拡縮を含めて座標系が完全に一致していること。
DAT-003
寸法または座標方向に疑義がある場合、自動拡縮・回転・位置合わせを行わず、その画像対を編集対象外とする。

3.2 原画像

DAT-008
読込形式はPNG、JPEG、BMP、TIFFとし、復号後の画素形式が8-bit RGBまたは8-bitグレースケールである画像だけを受理する。グレースケールは表示用にRGBへ展開する。
DAT-009
アルファ付き、索引色、CMYK、16-bit以上、浮動小数点その他の原画像形式は初期版では拒否する。無言の量子化や背景合成を行わない。
DAT-010
ICC色特性がある場合は表示計算用にsRGBへ変換し、存在しない場合はsRGBとして扱う。この変換は表示用メモリ上だけで行い、原ファイルを書き換えない。
DAT-011
EXIF/TIFF Orientationは「なし」または値1だけを許容する。値2～8は座標一致を保証できないため、自動適用せず当該画像対を拒否する。

「原画像を加工しない」とは、原ファイルおよび原解像度の意味画素を書き換えないことを指す。画面表示に必要なsRGB変換と倍率変更時の一時的補間は許容する。

3.3 三値画像・出力画像

  • 入力形式：8-bit PNG。RGBまたはグレースケールを許容する。
  • グレースケール値は 0 → 無、128 → 有、255 → 境界 と解釈する。
  • RGB値は (0,0,0)、(128,128,128)、(255,255,255) のみ許容する。
  • アルファチャンネル、16-bit、索引色、その他の色を含む入力は拒否する。
  • 内部表現は uint8 の二次元ラベル配列 0/1/2 とする。
  • 出力形式は2048 × 1536、8-bit RGB PNG、アルファなし、三色のみとする。

3.4 下端100画素の強制「無」化

画像座標は左上を原点 (0,0) とし、右方向を x 正、下方向を y 正とする。下端保護領域 P を次で定義する。

P = { (x, y) | 0 ≤ x ≤ 2047, 1436 ≤ y ≤ 1535 }
DAT-004
入力三値画像および既存の編集済み画像を開く際、形式・寸法・三色制約を画像全体について検証した後、内部ラベル配列の領域 P をすべて「無」0 へ設定する。下端領域に異常色があっても黒化で隠さず、入力不正として拒否する。
DAT-005
この規則は三値画像だけに適用する。原画像の下端100画素は加工せず、比較表示でも原画像本来の内容を維持する。
DAT-006
読込時の強制「無」化で一画素以上が変化した場合、現在画像を未保存状態とし、状態欄へ変更画素数と理由を表示する。自動変換自体はUndo・Redo履歴へ追加しない。
DAT-007
領域 P は作業中も保護領域とし、筆、塗り潰し、境界生成その他の画素変更操作による書換えを許可しない。保存時には防御的に同じ強制「無」化を再適用する。
基準配列との関係：読込時は強制無化直前の検証済み配列を基準配列とする。したがって下端に非無画素があった画像は、利用者が何も描かなくても保存するまで未保存状態となる。

4. ファイル対応付け・順序

4.1 フォルダ指定

利用者は原画像、三値画像、編集済み画像出力の三フォルダを個別に指定する。初期版は下位フォルダを探索しない。

PAIR-004
三フォルダは正規化した絶対パスと、可能な場合はWindowsの実体識別情報で比較する。ジャンクション、シンボリックリンク、大文字小文字差等を介して同じ実体を指す入力・出力フォルダの組合せを拒否する。

4.2 対応キー

原画像先頭三値画像先頭正規化群番号
①001001
②002002

拡張子を除いたファイル名を幹名とする。幹名をUnicode NFCへ正規化し、末尾27 Unicodeコードポイントを抽出する。一組の対応キーは次で定義する。

pair_key = (正規化群番号, NFC正規化した幹名の末尾27コードポイント)
PAIR-001
群番号と末尾27文字の双方が完全一致した原画像・三値画像だけを一組として採用する。対応判定は大文字小文字を区別し、曖昧一致や類似文字置換を行わない。
PAIR-002
幹名が27コードポイント未満、想定外の先頭、対応相手なし、同一キー重複は自動補完せず、対象外一覧へ記録する。
PAIR-003
単なる配列位置や一覧順だけで画像対を決定しない。

4.3 整列と移動対象

対応付け後の有効な画像対だけを編集用一覧に含め、三値画像のNFC正規化済み幹名を基準に、大文字小文字を区別しない自然順で整列する。同順位時は元の幹名、完全パスの順で補助比較する。

対象外画像は別のエラー一覧へ表示し、前後画像操作では停止せず自動的に飛ばす。これにより順序は有効画像対の中で連続する。

4.4 出力名

出力ファイル名は三値画像の幹名を継承し、拡張子を .png として出力フォルダ直下へ保存する。出力名衝突は一覧生成時に検出し、該当画像対を対象外とする。

5. 作業流れ・状態遷移

三フォルダ指定→対応・入力検査→画像対一覧生成→編集元選択→下端100px強制無化→表示・編集→明示保存→前後移動

5.1 現在画像の状態

状態意味
未読込有効な画像対が選択されていない。
読込済み・未変更現在配列と基準配列が完全一致する。
編集済み・未保存現在配列と基準配列が一画素以上異なる。
保存済み直前の正常保存で基準配列が現在配列へ更新され、対応する有効な出力が存在する。
処理中保存、塗り潰し、境界生成、小領域解析等を実行中。
STATE-001
未保存判定は現在配列と基準配列の内容比較で行う。高速化のためハッシュを用いてよいが、ハッシュ一致時に必要な完全比較を省略して誤判定してはならない。
STATE-002
履歴位置、操作回数、更新時刻だけを未保存判定の唯一の根拠にしない。編集によって基準配列と同じ内容へ戻った場合は未保存状態を解除する。
STATE-003
出力ファイルの存在を一覧上の「出力あり」として表示する。初期版では、保存せず確認だけ完了した状態を別管理しない。

5.2 未保存状態からの移動・終了

前画像、次画像、一覧選択、フォルダ再読込、アプリ終了のいずれでも、未保存変更がある場合は次を提示する。

選択肢動作
保存して続行保存成功後のみ遷移または終了する。失敗時は現在画像へ留まる。
変更を破棄して続行未保存変更と現在画像のUndo・Redo履歴を破棄して続行する。
中止遷移・終了を行わない。

5.3 移動先に編集済み画像がある場合

選択肢動作
編集済み画像から続ける出力画像を編集元として開く。以後の保存は同じ出力へ置換保存する。
入力三値画像から始める入力版を編集元として開く。既存出力は変更しない。後に保存する際、既存出力の上書きを再確認する。
中止移動しない。

5.4 変更不要画像

STATE-004
現在配列が基準配列と一致していても保存操作を許可する。対応する出力が存在しない場合は、正規化済み現在配列を通常の保存手順で出力し、「出力あり」とする。
STATE-005
出力が既に存在し、保存候補と内容が同一で外部変更もない場合は、再書込みを省略して「既に保存済み」と通知してよい。
進捗管理の範囲：変更不要画像も明示保存して出力を作る運用を採る。独立した確認済み台帳やサイドカー管理ファイルは初期版の対象外とする。

7. 表示仕様

7.1 レイヤ構成と表示可否

  1. キャンバス背景：画像外余白を示す中立色の表示領域。画像データには含めない。
  2. 下層：三値画像の表示像。
  3. 上層：原画像。
  4. 最前面：画像外枠、筆範囲、画素格子、小領域強調、下端保護領域の境界表示等の保存対象外オーバーレイ。
VIEW-011
原画像と三値画像は個別に表示・非表示を切り替えられる。原画像の不透明度は0～100％、初回既定値50％とする。
VIEW-012
三値画像が非表示の間は、筆、塗り潰し、境界生成、Undo、Redoその他のラベル配列を変更する操作を実行できない。履歴と未保存内容は保持し、再表示後に操作を再開できる。
VIEW-013
三値画像が非表示の間は、小領域強調と筆範囲を表示しない。画素格子と画像外枠は表示設定に従う。

7.2 原画像の表示変換

原画像は3.2の規則で表示用sRGB 8-bit RGBへ変換する。この表示用配列を原解像度の比較計算へ用い、原ファイル自体へ保存しない。

VIEW-014
100％表示では原画像・三値画像とも一画像画素を一表示論理画素へ対応させ、座標のずれや先行補間を生じさせない。

7.3 GIMP互換比較モード

解釈固定：三値画像を通常の不透明基底、原画像を上層の「比較（明）」として扱う。既定キー名やGIMPの将来版ではなく、以下の数式を規範とする。

三値表示画素を T、原画像画素を O、原画像不透明度を α とする。sRGB 8-bit成分を0～1へ正規化し、2048×1536の原解像度上でRGB成分ごとに計算する。

M = max(T, O)
DisplayNative = (1 - α) × T + α × M
  • α = 0 では三値画像だけを表示する。
  • α = 1 では max(T, O) を表示する。
  • 合成後の DisplayNative をキャンバス倍率へ拡縮する。各レイヤを別々に縮小してから合成しない。
  • GIMP互換受入試験は100％表示で行い、8-bit出力の差が各成分±1以内なら合格とする。

7.4 疑似色モード

三値の保存値は変更せず、表示時のみ高色差の疑似色へ写像する。初期配色は次とし、設定画面で変更可能とする。

ラベル保存色初期疑似色
無#000000#204060（濃青）
有#808080#FF3B7A（赤紫）
境界#FFFFFF#FFE600（黄）

疑似色モードでは原解像度上で通常のアルファ合成を行い、その完成像を表示倍率へ拡縮する。疑似色、格子、警告表示は保存画像へ含めない。

7.5 拡大・縮小・表示範囲移動

VIEW-001
マウスホイール上方向で一段拡大、下方向で一段縮小し、操作開始時のポインタ直下にある画像座標を可能な限り固定する。一段は現倍率×1.25または÷1.25とする。
VIEW-002
表示倍率は5％～6400％。100％表示と全体表示を用意する。範囲外へは進まず端値で停止する。
VIEW-003
中ボタンドラッグ、または現在「一時パン操作」に割り当てられた保持キー＋左ドラッグで表示範囲を移動する。保持キーの初期割当はSpaceとする。
VIEW-004
画像切替時は倍率と表示中心座標を維持する。ただし全体表示中は切替先も全体表示とする。
VIEW-005
原解像度で合成した完成像は、100％超で最近傍補間、100％未満で高品質縮小補間を用いて表示する。元画像およびラベル配列は変更しない。
VIEW-006
表示範囲移動は画像矩形の内側へ制限せず、画像外の仮想余白まで許可する。画像の各辺および各隅をキャンバス表示領域の中央まで移動できること。
VIEW-007
キャンバス表示領域を幅 Vw・高さ Vh、現在倍率での画像表示寸法を幅 Iw・高さ Ih、画像左上の表示座標を (x,y) としたとき、パン可能範囲を原則として Vw/2 - Iw ≤ x ≤ Vw/2、Vh/2 - Ih ≤ y ≤ Vh/2 とする。
VIEW-008
画像外余白は画像と判別できる中立色または市松模様で表示し、画像境界には保存対象外の明瞭な外枠を表示する。画像外での筆・塗り潰し・画素参照は作用しない。
VIEW-009
全体表示では画像全体を中央配置し、キャンバス寸法が許す限り上下左右に各32論理画素以上の余白を確保する。画像全体表示を余白より優先する。
VIEW-010
下端保護領域の上端 y=1436 に保存対象外の識別線を表示し、必要に応じて薄い網掛けを重ねる。
VIEW-015
全体表示中にウィンドウまたはキャンバス寸法が変化した場合は全体表示倍率を再計算する。手動倍率中は画像中心座標と倍率を維持し、表示可能範囲だけを再制限する。

7.6 画素格子

格子設定は「自動表示ON」と「自動表示OFF」の二状態とする。

VIEW-016
自動表示ONでは、一画像画素が実画面上で8機器画素以上の幅を占める場合だけ格子を表示する。自動表示OFFでは倍率にかかわらず表示しない。低倍率での常時表示モードは設けない。
  • 格子線は1実画面画素、半透明、保存対象外。
  • Windowsの表示倍率と機器画素比を反映して判定する。

7.7 座標精度・DPI変更

VIEW-017
ズーム、パン、DPI倍率にかかわらず、画面座標から画像座標への変換誤差で隣接画素を編集してはならない。筆ポインタは実際の変更範囲を示す。
VIEW-018
ウィンドウを異なるDPIのモニターへ移動した場合、機器画素比、格子判定、低倍率筆判定を再計算し、表示中心の画像座標を維持する。

8. 編集機能

8.1 共通

  • 編集対象は三値ラベル配列だけとする。
  • 選択色は「無」「有」「境界」の三つだけ。
  • 半透明、ぼかし、アンチエイリアス、中間色を生成しない。
  • 表示用疑似色を編集値として書き込まない。
  • 下端保護領域 P を全画素変更操作の対象外とする。
  • 三値画像が非表示の場合は画素変更操作を開始できない。

8.2 選択色の直接・循環切替

EDIT-001
現在の選択ラベルを「無」0、「有」1、「境界」2のいずれか一つとして保持し、筆と塗り潰しが同じ状態を使用する。初回起動時および再起動時の既定値は「有」とする。
EDIT-002
利用者は画面上の直接選択、順方向循環、逆方向循環、メニュー、割当キーのいずれからも選択ラベルを変更できる。
EDIT-003
順方向循環は 無 → 有 → 境界 → 無、逆方向循環は 無 → 境界 → 有 → 無 の固定順序とし、一入力につき一段だけ巡回する。
EDIT-004
循環順序は内部ラベル値を基準とし、疑似色のRGB値や表示状態によって変えない。
EDIT-005
選択ラベル変更は画像画素、未保存状態、履歴、道具、倍率、表示位置へ影響させない。画像を前後移動しても同一起動中は維持し、アプリ再起動時は「有」へ戻す。
EDIT-006
変更後は編集欄、筆ポインタ、状態欄を直ちに更新し、意味名と保存色を確認できること。

8.3 筆

形状円形、正方形
筆径1～512画像画素、初回既定値5。増減操作一回につき±1画素。
操作左押下から解放まで描画し、ドラッグ点間を補間する。
範囲画像矩形内かつ y≤1435 の部分だけを変更する。
Undo単位一回の押下から正常解放までを一操作とする。
EDIT-007
筆跡は押下時点の選択ラベル、筆径、形状を固定して完了させる。描画中にこれらの変更操作を入力しても発火・予約しない。
EDIT-008
正方形筆はD×D画素の矩形とする。円形筆はD×D外接矩形内の画素中心について、正規化楕円式が1以下となる画素を含める。偶数径ではポインタ下画素を中央四画素の左上側として、余剰一画素を+x、+y方向へ配する。画面上の筆範囲はこの離散マスクと完全一致させる。
円形マスク（i,j = 0..D-1）
((i + 0.5 - D/2) / (D/2))² + ((j + 0.5 - D/2) / (D/2))² ≤ 1

低倍率では、画面上の筆径が4実画面画素以上の場合だけ描画を許可する。

editable = brush_diameter × display_scale × device_pixel_ratio ≥ 4

8.4 塗り潰し

  • クリック地点と同じ内部ラベル値を持ち、上下左右で連続する領域を選択色へ置換する。
  • 四近傍連結を用い、斜め方向だけで接する同色領域は含めない。
  • 下端保護領域は探索不能な壁として扱う。
  • 許容差は設けない。対象色と選択色が同じ場合は変更も履歴追加もしない。
  • 一回の塗り潰しを一つのUndo単位とし、結果を一括反映する。
  • 低倍率筆径制限の対象外とする。

8.5 描画中の排他と取消

EDIT-009
筆の左押下から解放まで、マウス移動、解放、固定取消キーEsc以外のアプリケーション命令を無効化する。入力を描画後へ予約して実行してはならない。
EDIT-010
正常なマウス解放では筆跡を確定する。Esc、ウィンドウ非アクティブ化、ポインタ捕捉喪失、アプリケーション例外が生じた場合は、現在の筆跡全体を押下前へ戻して履歴へ追加しない。
EDIT-011
画像外で解放されてもポインタ捕捉が維持されている場合は、画像内へ描かれた部分だけを正常確定する。
固定例外：Escは進行中操作を安全に取り消すための予約キーとし、操作割当の変更対象にしない。

9. Undo・Redoと未保存判定

HIST-001
筆、塗り潰し、境界生成をUndo・Redo対象とする。
HIST-002
表示倍率、表示位置、不透明度、疑似色、格子、小領域表示、選択ラベル、設定変更は履歴へ入れない。
HIST-003
Undo後に新しい編集を行った場合、その時点より先のRedo履歴を破棄する。
HIST-004
正常保存後は現在配列の複製を新しい基準配列とする。保存時の履歴位置も記録してよいが、未保存判定の唯一の根拠にしない。
HIST-005
履歴は現在画像の編集セッションだけ保持し、画像を離れた時点で破棄する。再訪時に過去セッションのUndoは復元しない。
HIST-006
履歴の古い項目または保存位置が上限により破棄されても、基準配列との内容比較による未保存判定を維持する。
HIST-007
三値画像が非表示の間はUndo・Redo操作を無効化するが、履歴自体は破棄しない。

履歴上限は「200操作」または「512MiB」の先に到達した方とし、超過時は古い履歴から破棄して状態欄へ通知する。

読込時の下端強制無化は入力正規化であり、Undo・Redo対象にしない。ただし強制無化前の配列を基準とするため、差分がある場合は保存まで未保存状態となる。

10. 自動境界生成

10.1 共通仕様

  • 現在画像全体を対象とし、三値画像が表示中の場合だけ実行可能とする。
  • 四近傍だけを用いる。斜め接触だけでは太さ1の境界を生成しない。
  • 境界太さは1～64画素、初回既定値1。増減操作一回につき±1画素。
  • 処理開始時点のラベル配列を基準に対象を一括決定し、完了時に一括反映する。
  • 一回の実行全体を一つのUndo単位とし、Redo可能とする。
  • 変更画素が0の場合は履歴へ追加しない。
  • 処理後に小領域検出結果を再計算する。
  • 原画像は変更しない。
  • 下端保護領域は「無」として距離計算の基準に含めてよいが、書換対象から必ず除外する。

画面の「境界を生成」ボタン、メニュー、または現在割り当てられたキーから実行する。既定割当は Ctrl+Shift+B とする。

10.2 モードA：無側へ生成

既存方式「有」と「無」が直接接し、間に「境界」がない箇所について、無側の画素を境界へ変更する。

  1. 四近傍に「有」がある「無」画素を接触種 S0 とする。
  2. 太さ1では S0 を「境界」へ変更する。
  3. 太さNでは、S0 から「無」画素だけを通る四近傍距離 0～N-1 の「無」画素を変更する。
  4. 既存「境界」は通過元にも書換対象にもせず、「無－境界－有」では新たに生成しない。
  5. 「有」と既存「境界」は変更しない。
太さ1
処理前: 無 有 有
処理後: 境 有 有

既存境界あり
処理前: 無 境 有
処理後: 無 境 有

10.3 モードB：非無側へ生成

追加方式「無」と「有または境界」の境界について、有・境界側を一定幅の境界へ変更し、黒側は維持する。

  1. 処理開始時点の「無」を基準集合とする。
  2. 各非無画素について、「無」から非無画素だけを通る四近傍最短距離を求める。
  3. 距離1～Nの「有」または「境界」を「境界」へ設定する。
  4. 既存境界を最終幅へ数え、同じ太さで繰り返しても太くしない。
  5. 「無」は変更せず、画像外部を「無」とみなさない。
太さ1
処理前: 無 有 有
処理後: 無 境 有

既存境界あり・太さ2
処理前: 無 境 有 有
処理後: 無 境 境 有
注意：幅の狭い「有」領域は全体が境界へ変わり得る。これは正常動作であり、Undoで戻せる。

「有」と「境界」を色ごとに分離し、それぞれ八近傍連結成分を求める。両色を同一成分として結合しない。

面積1～50画素の成分を対象とし、50画素ちょうどを含む。「無」は対象外。

  • 対象画素へ半透明の警告色を重畳する。
  • 成分の外接矩形を2実画面画素の警告線で表示する。
  • 警告色は疑似色と区別できる白黒交互または高彩度の縞表示とする。

11.2 再計算契機

  • 画像読込後
  • 筆描画終了後
  • 塗り潰し完了後
  • Undo・Redo後
  • 境界生成後
  • 表示をOFFからONへ切り替え、結果が現改訂番号と一致しない時

12. 保存・既存出力・競合制御

12.1 明示保存

SAVE-001
正式保存は保存ボタン、メニュー、または現在「保存」に割り当てられたキーから実行する。既定割当は Ctrl+S とする。画像移動時の「保存して続行」も同じ処理を呼ぶ。
SAVE-002
入力原画像・入力三値画像を上書きしない。
SAVE-003
疑似色、原画像、格子、筆ポインタ、小領域警告を保存しない。内部ラベル配列から直接PNGを生成する。
SAVE-004
保存用ラベル配列は現在配列の複製から作成し、PNG生成直前に下端保護領域 P をすべて「無」へ再設定する。
SAVE-005
保存後の再読込検査では、寸法、8-bit RGB、アルファなし、三色制約、領域 P の全黒を必須とする。
SAVE-006
未変更状態でも保存できる。出力が存在しない場合は通常どおり新規作成し、変更不要画像の作業済み目印として「出力あり」にする。

12.2 原子的保存

  1. 対象出力に対する排他的な保存ロックを取得する。取得できなければ保存しない。
  2. 外部変更を再検査する。
  3. 現在配列を保存用配列へ複製し、下端100画素を「無」へ強制する。
  4. 出力フォルダ内へ一時PNGを書き出す。
  5. 一時PNGを再読込し、全出力条件を検証する。
  6. 検証成功後、OSの置換操作で正式ファイルへ反映する。
  7. 正式ファイルの内容ハッシュを取得し、現在配列を新しい基準配列として未保存状態を解除する。
  8. 失敗時は既存出力へ触れず、一時ファイルを削除し、未保存状態を維持する。

12.3 内容ハッシュと外部変更

SAVE-007
画像読込時に原画像、入力三値画像、編集元出力のSHA-256を記録する。出力が存在しない場合は「不存在」を基準状態として記録する。
SAVE-008
保存ロック取得後、正式書出し前に各ファイルを再検査する。出力の内容変更または新規出現を検出した場合、「外部版を開く」「現在内容で上書き」「中止」を提示し、初期選択を中止とする。
SAVE-009
原画像または入力三値画像の外部変更を検出した場合、「再読込して現在編集を破棄」「読込済みスナップショットを明示確認の上で保存」「中止」を提示し、初期選択を中止とする。
SAVE-010
更新時刻だけで競合を判定しない。ハッシュ検査と保存ロックを、検査から置換まで同じ排他区間で行う。

12.4 既存出力

  • 編集済み画像を編集元として開いた場合、通常の保存で同じ出力を置換する。
  • 既存出力を無視して入力三値画像から開いた場合、最初の保存時に既存出力の上書きを確認する。
  • 保存候補と既存出力が内容上同一で競合がない場合、物理再書込みを省略してよい。
  • 一覧上の「出力あり」はファイル存在を示す。実際に開く際は入力条件を完全検査し、不正なら「出力不正」と表示する。

12.5 異常終了

初期版では未保存編集の自動復元を必須としない。異常終了時に未保存変更が失われ得ることを利用者向け説明へ明記する。正式出力と入力は原子的保存および排他制御で保護する。

  • Windows 10 / 11 64-bit
  • Python 3.11.x
  • オフラインで全機能を利用可能
  • 日本語・丸数字を含むUnicodeパスに対応
  • Windows表示倍率100～200％および異なるDPIの複数モニターで座標精度を維持

14.2 データ完全性

  • 原画像と入力三値画像へ書込みを行わない。
  • 保存前後に三色制約、寸法、下端100画素の全黒制約を検証する。

  • 例外発生時も正式出力を半端な状態へ置換しない。
  • 外部変更はSHA-256で検査し、出力置換区間は排他ロックで保護する。
  • 内部ラベル配列に対する画素変更処理の終了時、下端保護領域が全て値0であることを表明検査できる構成とする。

AT-041待機開始前の押下除外・自動反復待機開始時から押されているキーを解放するまで取得せず、長押しによる自動反復でも一度だけ候補化する。
AT-042入力待機の取消Esc、画面非アクティブ化、別欄選択の各操作で待機が解除され、変更前の割当を維持する。
AT-043予約入力の拒否修飾キー単独、Tab、Alt+F4等を割り当てず、理由を表示して安全に待機または取消できる。
AT-044割当競合既存操作と同じキーを候補化した際に競合元を表示し、移動を選ぶと旧割当だけが解除され、取消では双方とも変化しない。
AT-045主・副割当一操作へ異なる二つのキーを登録して双方から実行でき、同一キーの二重登録は作られない。
AT-046適用・キャンセル適用前の作業値は実行割当へ影響せず、「適用」で有効化・保存され、「キャンセル」で開画面時点へ戻る。
AT-047永続化と版差分再起動後に割当が復元され、未知IDを無視し、欠落した新規操作だけ既定値で補完する。
AT-048割当解除・既定復元個別解除、個別既定復元、全体既定復元が指定どおりに動作し、画像の未保存状態と履歴を変更しない。
AT-049設定画面への到達保証設定を開くキーを含む全割当を解除しても、メニューまたは常設ボタンから設定画面へ到達でき、主画面上の各操作もGUIから実行できる。
AT-050論理キー・日本語入力方式日本語入力方式ON/OFFで論理キー取得結果が変わらず、物理走査符号ではなくPortableText相当で保存し、現在のWindowsキーボード配列に応じたNativeText相当で表示する。
AT-051選択色の順方向循環任意の開始色から循環操作を繰り返すと、無 → 有 → 境界 → 無の順に一入力一段で切り替わり、三回で開始色へ戻る。
AT-052選択色の逆方向循環任意の開始色から逆循環操作を繰り返すと、無 → 境界 → 有 → 無の順に切り替わり、三回で開始色へ戻る。
AT-053循環と疑似色の独立三つの疑似色を任意に変更しても循環順序が変わらず、編集欄と状態欄には意味名および保存色が正しく表示される。
AT-054色切替の非編集性と状態維持直接選択・順循環・逆循環のいずれもラベル配列、未保存状態、Undo・Redo履歴、選択中の道具を変更せず、前後画像へ移動しても同一起動中の選択色を維持する。
AT-055色循環の割当と描画中排他label.cycle-forwardとlabel.cycle-backwardを設定画面で任意キーへ変更・永続化できる。筆押下中は色切替が発火せず、筆跡全体が押下時の一色だけで描かれる。
AT-056色循環の操作経路一致編集メニュー、画面上の前後循環ボタンを実装した場合の当該ボタン、および割当キーから同じ操作を実行したとき、選択色、状態欄、筆ポインタが同一結果となり、いずれの経路も画像画素を変更しない。
AT-057既定キーと変更後キー保存を任意キーへ変更・適用すると新割当だけで実行でき、本文記載のCtrl+Sは既定値に過ぎず固定入力として残らない。
AT-058操作一回分と上下限筆径±1px、境界太さ±1px、不透明度±5pt、倍率×／÷1.25で変化し、各範囲端で停止する。
AT-059キー自動反復刻み操作は反復KeyDownごとに一段進み、保存・画像移動・色循環・境界生成等の単発操作は長押ししても一度だけ実行され、保持操作は解放まで有効になる。
AT-060初回既定値初期設定削除後の起動で、両画像表示、疑似色OFF、不透明度50％、格子自動ON、筆・円形・5px、有、無側・1px、全体表示となる。
AT-061設定永続化範囲保持対象は再起動後に復元され、選択ラベル、倍率、中心、現在画像は復元されず規定初期値になる。
AT-062設定の適用・取消適用で即時反映・保存、OKで反映後に閉じ、取消で未適用変更だけを破棄し、画像の未保存状態を変えない。
AT-063疑似色設定#RRGGBB入力と色選択が一致し、アルファを設定できず、色差64未満では警告し、明示確認後は適用でき、既定復元と再起動後復元が動作する。
AT-064原画像入力条件・色管理8-bit RGB/Lを受理し、ICC付き画像をsRGB表示へ変換する。アルファ、索引色、CMYK、16-bit、Orientation 2～8を拒否し、原ファイルを変更しない。
AT-065三値非表示時の編集禁止三値を隠すと筆・塗り潰し・境界生成・Undo・Redoが無効になり、小領域・筆範囲が隠れ、再表示後に履歴と未保存内容が維持される。
AT-066変更なし保存未変更かつ出力なしの画像で保存すると正規化済みPNGが作成され「出力あり」になる。既存同一出力では再書込みを省略できる。
AT-067内容比較による未保存判定編集後に画素内容を基準配列と完全同一へ戻すと未保存表示が解除され、履歴位置が異なっていても保存確認が発生しない。
AT-068履歴破棄後の未保存判定履歴上限で保存位置を含む古い履歴が破棄されても、基準配列との差分に従って未保存状態が正しく維持・解除される。
AT-069外部出力変更・新規出現読込後に出力を別内容へ変更または新規作成すると保存前SHA-256検査で検出し、外部版・上書き・中止を提示して初期選択が中止になる。
AT-070多重起動保存ロック別プロセスが同じ出力の保存ロックを保持中は保存せず、既存出力と未保存内容を維持する。
AT-071筆描画の原子性と取消描画中の他命令は発火・予約されず、Esc・非アクティブ化・捕捉喪失で筆跡全体が戻り、正常解放では一履歴単位として確定する。
AT-072偶数径筆マスク円形・正方形の偶数径で仕様どおり+x/+y側へ余剰画素が配され、ポインタ表示と実変更画素が完全一致する。
AT-073ウィンドウ寸法変更全体表示中は再フィットし、手動倍率中は倍率と中心画像座標を維持してパン範囲だけ再制限する。

17. 推奨実装構成 参考設計

領域推奨
GUIPySide6。画像キャンバスはQGraphicsViewまたは専用QWidget。
原画像復号Pillow＋ImageCms。8-bit L/RGBだけを受理し、ICCがあればsRGBへ表示変換。Orientation 2～8は拒否。
三値内部表現NumPy uint8[1536,2048]、値0/1/2。labels[1436:1536,:] を共通保護マスクで管理。
基準・未保存基準配列を保持し、改訂時に高速ハッシュを更新。ハッシュ一致時は必要に応じて numpy.array_equal で確定する。
画素処理NumPy＋OpenCVまたはSciPy。連結成分、距離、膨張は作業配列で計算後に一括反映。
筆トランザクション押下時の設定と変更前差分を保持し、正常解放で確定、Esc・捕捉喪失で全差分を復元。
Undo変更矩形または変更画素のbefore/after差分を命令単位で保持。基準配列とは独立。
表示原解像度上で合成してDisplayNativeを作成し、完成像を倍率へ拡縮。保存データ、表示像、オーバーレイを分離。
非同期処理QThreadPool等を用い、画像改訂番号で古い小領域結果を破棄。
保存・競合SHA-256、対象出力単位の排他ロック、一時PNG、再検査、os.replace。ロック取得後にハッシュを再確認。
操作管理操作ID、操作型、刻み量、自動反復可否、主副割当をAction Registryへ一元化。ボタン、メニュー、キーが同じ命令を参照。
キー取得QKeyEventから論理キー＋修飾キーを取得。PortableTextで保存、NativeTextで表示。走査符号は使用しない。
設定QSettings。スキーマ版、操作割当、フォルダ、表示、疑似色、筆、境界、ウィンドウ状態を保存。選択ラベル、倍率、中心、未保存内容は保存しない。
設計上の要点：入力、基準配列、現在配列、表示像、オーバーレイ、出力を別物として管理する。ショートカットとボタン、履歴位置と未保存判定、画面表示と保存データを同一視しない。人間は同じに見える物を同じ変数へ詰めたがるが、後で必ず報復される。

18. 推奨開発順序

  1. データ層：Unicode対応キー、入力検査、原画像sRGB表示変換、三値配列、基準配列、下端保護、ハッシュ。
  2. 保存層：変更なし保存、出力状態、排他ロック、外部変更検査、原子的保存。
  3. 閲覧層：原解像度合成、疑似色、レイヤ表示、ズーム、パン、余白、格子、DPI変更。
  4. 基本編集：選択色、円・正方形筆マスク、筆トランザクション、塗り潰し、三値非表示時排他。
  5. 履歴：Undo・Redo、基準配列との内容比較、履歴上限。
  6. 規則処理：二種の境界生成、太さ、保護領域、全体Undo。
  7. 検査支援：小領域解析、色別件数、警告オーバーレイ、改訂番号。
  8. 遷移・異常系：未保存確認、既存出力選択、対象外一覧、フォーカス喪失、保存競合。
  9. 設定：初期値・永続化、疑似色設定、Action Registry、キー入力待機、操作型、反復、競合解決。
  10. 受入・配布：AT-001～079、自動算法試験、Windows実機、高DPI、日本語入力方式、複数モニター、多重起動、配布手順。

19. 初期版の対象外

  • 画像の自動位置合わせ、回転、拡縮、切抜き。
  • 原画像から正解三値画像を推論する機械学習。
  • 四値以上のラベル、任意保存色、半透明ラベル。
  • 下位フォルダの再帰探索。
  • 複数画像を未保存のまま同時保持するタブ編集。
  • 選択範囲、直線、スポイト、コピー・貼り付け、前後画像複製。
  • 選択範囲だけの境界生成。
  • 異常終了後の未保存編集自動復元。
  • 出力とは独立した確認済み台帳、作業者、日時等の進捗管理。
  • 物理走査符号または鍵盤位置に基づくキー割当、複数段キーシーケンス。
  • マウスボタン、ホイール方向、ドラッグジェスチャー自体の再割当。
  • アルファ、索引色、CMYK、16-bit以上の原画像。
  • macOS・Linux対応、Web版、複数人同時編集。
