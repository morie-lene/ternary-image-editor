## 0. 読者と用途

本追補は実装者と試験者が、入力画像群の対応付け、三値JPEGの取込、編集元の選択、保存済み出力からの
再開、画像寸法、下端保護を同じ契約で照合するための規範文書である。利用者向けの短い操作手順はREADMEに置く。
本書の `FLEX-*` は実装が満たすべき状態を表し、現在の実装完了やWindows配布受理を単独では
主張しない。現在状態と証拠は要求追跡表の `FLEX-AT-*` を参照する。

## 2. 用語と入力群境界

### FLEX-DATA-001 対応形式画像

入力フォルダ直下にある通常ファイルのうち、次の拡張子を大文字小文字を区別せず対応形式画像と
する。下位フォルダは探索しない。

- 原画像: `.png`、`.jpg`、`.jpeg`、`.bmp`、`.tif`、`.tiff`
- 三値画像: `.png`、`.jpg`、`.jpeg`

拡張子が対応外のファイルは候補数へ含めず、理由付き対象外項目として表示する。対応拡張子を持つ
ファイルは、ファイル名が厳格対応キーに適合するか、復号後の画像内容が正しいかにかかわらず、
候補数へ含める。ファイル名と画像内容の検査は件数検査と別の段階で行う。

### FLEX-DATA-002 画像群の件数門

原画像群と三値画像群は、対応形式画像をそれぞれ1件以上含み、その件数が同一でなければならない。
片方が0件、または件数が異なる場合は画像対を一件も導入せず、両群の候補数を示して読込を止める。
短い側に合わせた切捨て、余剰ファイルの黙示無視、別方式への自動fallbackを行わない。

この件数一致は「正しく対応した」ことの証明ではない。厳格対応ではキー検査、自然順対応では
全対応表に対する利用者確認を別に要求する。

## 3. 対応付け方式

### FLEX-PAIR-001 厳格対応

既定方式は「仕様キーで厳格対応」とする。方式を保存していても、初回状態および不明・破損値からの
復旧先は厳格対応とする。自然順対応へ黙って切り替えない。

厳格対応ではv1.5のキー規則を維持する。

- 原画像の幹名先頭 `①` / `②` を群 `001` / `002` とする。
- 三値画像の幹名先頭 `001` / `002` を同名の群とする。
- 幹名をUnicode NFCへ正規化し、末尾27 Unicodeコードポイントを比較する。
- 群と末尾が大文字小文字を含め完全一致した一対だけを対応させる。
- 想定外の先頭、短い幹名、重複、相手欠落、出力名衝突は理由付き対象外とする。

件数門を通った後でも、厳格キーに適合しないファイルを順番だけで補完してはならない。

### FLEX-PAIR-002 自然順対応

「ファイル名の自然順で対応」は利用者が明示選択した場合だけ使う。原画像群と三値画像群を別々に
整列し、同じ一覧位置のファイルを一対とする。厳格対応の失敗を契機とした自動fallbackにはしない。

整列専用の比較値は拡張子を含むファイル名をUnicode NFKCへ正規化し、十進数字の連続部分を数値、
その他を大文字小文字非依存の文字列として比較する。同順位はNFKC後のファイル名を大文字小文字
非依存で比較し、さらに絶対pathで決定的に解決する。NFKCは整列だけに使い、ファイルまたは厳格
対応キーの同一性を変更しない。

出力名は各三値画像の幹名に `.png` を付けた物とする。Windowsで同じ出力名になる衝突が一件でも
あれば、自然順の対応全体を導入しない。

### FLEX-PAIR-003 全対応表の毎回確認

自然順対応を導入する前に、番号、原画像名、三値画像名、出力PNG名を全件並べた対応表を表示する。
利用者が「この対応で読み込む」を明示した場合だけ導入する。中止を既定選択とし、中止時は現在の
画像集合、編集内容、出力先を変更しない。

確認結果は永続的な許可として再利用しない。フォルダ選択、保存済みフォルダの起動時再走査、手動
再走査など、自然順の対応計画を作るたびに全表を再表示し、改めて確認を得る。

## 4. 参照専用原画像

### FLEX-ORIG-001 復号可能性と表示正規化

原画像は編集・保存対象ではなく、三値ラベル編集の参照表示にだけ用いる。`FLEX-DATA-001`の対応
拡張子を持ち、Pillowで画像として復号できることを必要条件とする。復号後の色模型、bit深度、
アルファ、索引色、CMYK、追加sample、EXIF / TIFF Orientationは、それ自体を拒否理由にしない。
原画像へ三値画像用の色値検査を適用しない。

原画像はメモリ上だけでEXIF Orientationを表示方向へ反映し、表示用RGBへ変換する。埋込ICC色特性を
解釈できる場合はsRGBへ変換する。ICCがない場合、空または壊れている場合、変換できない場合は、
通常のRGB変換へ退避して表示を継続する。この退避は厳密な色再現を保証しないが、参照表示を不必要に
止めないための規則である。原画像を改名、移動、上書き、別形式保存しない。

復号不能、読込中の外部変更、Pillowの展開爆弾制限、幅または高さが正でない画像は拒否する。
確認画面は表示せず、拒否時だけ対象pathと理由を示す。

### FLEX-ORIG-002 表示寸法の照合（version 1.1、置換済み）

version 1.1では、原画像の寸法をEXIF Orientationの表示方向反映後に確定し、入力三値画像と常に
照合していた。この識別子は履歴として残し、version 1.2の編集元別寸法契約には用いない。現行契約は
`FLEX-DIM-005`とする。

## 5. 三値JPEGの取込

### FLEX-JPEG-001 警告と取消既定

三値画像がJPEGなら、その画像を開く直前に不可逆な三値化を行う旨、変換規則、入力不変、保存先が
PNGであることを警告する。「中止」を既定およびEscape時の選択とし、利用者が「三値化して開く」を
明示した場合だけ復号・三値化する。許可は画像一件ごとに得て、後続JPEGへ流用しない。

### FLEX-JPEG-002 受理するJPEG

実形式がJPEGで、復号後が8-bit RGBまたは8-bitグレースケールであり、正の幅と高さを持つ画像だけを
受理する。透明情報、CMYK等の別色模型、EXIF Orientation 2〜8、復号不能画像は自動補正せず拒否する。

埋込ICC色特性がある場合は、メモリ上でICC変換を行ってsRGBへ変換した後に三値化する。ICCがない
場合は復号したRGB値をsRGB入力値として三値化へ渡す。不正なICC色特性を黙って無視してはならない。

### FLEX-JPEG-003 決定的三値化

三値化の保存色 `SAVE_RGB` とラベル順は次に固定する。

| ラベル | 保存色 |
| --- | --- |
| 0 | `(0, 0, 0)` |
| 1 | `(128, 128, 128)` |
| 2 | `(255, 255, 255)` |

sRGB画素 `p=(R,G,B)` と保存色 `c` の距離を
`d(p,c)=(R-cR)^2+(G-cG)^2+(B-cB)^2` とし、距離が最小のラベルへ一画素ずつ割り当てる。
同距離なら数値が小さいラベルを採る。乱数、dither、周辺画素参照、画像ごとの自動閾値を使わない。

### FLEX-JPEG-004 入力不変と保存

JPEGの復号、ICC変換、三値化、下端正規化はメモリ上だけで行い、入力JPEGを改名、移動、上書き、
PNG化しない。三値化後は未保存状態とし、既存の明示保存操作を行った場合だけ出力フォルダへ
8-bit RGB、アルファなし、三保存色だけのPNGとして保存する。

厳格な三色PNG入力は従来どおり色を再量子化しない。PNGに許容外の色があればJPEG規則へ
fallbackせず拒否する。

## 6. 編集元の優先順位

### FLEX-SOURCE-001 既存出力の自動優先（version 1.1、置換済み）

version 1.1では、正常な既存出力を無対話で優先する一方、出力を選んだ後も入力三値画像の形式、寸法、
内容指紋を検査した。この識別子と挙動は履歴として残し、version 1.2の再開契約には用いない。

### FLEX-SOURCE-002 選択ラベル源と編集用画像対

対応付けに用いる画像対は、`FLEX-DATA-002`どおり原画像と入力三値画像の非零同数を前提とする。この
対応付け上の画像対と、実際に開く「編集用画像対」を分ける。編集用画像対は、原画像と、選択ラベル源
一件から成る。選択ラベル源は `INPUT` または `OUTPUT` のいずれかである。

既存の編集済み出力PNGがある場合は `OUTPUT` を自動優先し、正常なら入力版との選択確認を表示しない。
出力がない場合、または `FLEX-SOURCE-003`の確認を経て入力版へ切り替えた場合だけ `INPUT` を選ぶ。

`FLEX-DATA-002`の件数門を通って対応計画が成立した後に`OUTPUT`を選んだ場合、入力三値画像は
対応付け用のpathと名前にすぎない。入力三値画像の内容を開かず、実形式、色、寸法、Orientation、
内容指紋を検査せず、保存時の変更検査にも用いない。対応計画成立後の`OUTPUT`読込、および既に開いた
`OUTPUT`セッションの編集・保存では、未使用入力が壊れている、読めない、内容が変わった、または
実体が失われたことだけを理由に止めない。冷間起動、フォルダ選択、再走査で新しい対応計画を作る時は
`FLEX-DATA-002`の件数門を改めて適用する。`INPUT`を選んだ場合は、PNGまたはJPEGの既存の厳格検査、
必要なJPEG確認、内容指紋取得を従来どおり行う。

### FLEX-SOURCE-003 不正出力fallbackのsnapshot許可

既存出力が復号不能、形式・色・Orientation・寸法不正、または読込中に変更され、直接指定など確認可能な
経路で入力版への切替え判断が必要な場合は、理由と対象pathを示して利用者に確認する。無言でfallback
しない。preflightと未確認snapshotへの前後移動は`FLEX-SOURCE-004`どおりmodalなしで飛ばす。
利用者が切替えを許可した結果は、
その時点の出力path、存在状態、内容指紋から成る出力snapshotにだけ結び付ける。同じsnapshotを同じ走査・
移動経路で再評価しても確認を繰り返さない。出力の新規出現、削除、置換、内容変更を検出した場合は、
再検査し、なお不正なら新しいsnapshotについて改めて確認する。

入力版へ切り替えた後に既存出力を置換保存する場合は、fallback許可を置換許可へ流用せず、既存の
置換確認を別に行う。

### FLEX-SOURCE-004 読込通知と失敗cacheの範囲

フォルダ選択、起動時再走査、手動再走査のpreflight、および「前へ」「次へ」による探索では、開けない
候補を飛ばして次を探索し、候補一件ごとのmodal診断を表示しない。理由は対象外一覧または状態表示へ
集約する。利用者が一覧の特定行を直接開いた場合だけ、その行について対象pathと理由を持つmodalを
一回表示する。不正出力なら、この一回は`FLEX-SOURCE-003`のfallback確認を兼ね、取消後に同じ理由の
診断を重ねない。

出力だけに由来する失敗と、原因を分類できない例外を、画像対全体が恒久的に開けないというcacheへ
格上げしない。出力の変更後や別の選択ラベル源で再試行できるようにする。恒久cacheへ入れられるのは、
当該画像対そのものに属し、選択ラベル源や出力snapshotの変更では解消しないと判定できる失敗だけとする。

## 7. 寸法と下端保護

### FLEX-DIM-001 任意の正寸法

アプリケーションの入力寸法を `2048×1536` に固定しない。幅と高さがともに正で、各形式の復号条件を
満たす画像を候補にできる。`2048×1536`は想定用途および性能測定に使う代表実寸であって、読込要件
ではない。

### FLEX-DIM-002 画像対の同寸（version 1.1、置換済み）

version 1.1では、選択ラベル源にかかわらず原画像と入力三値画像を復号し、同寸を要求した。この
識別子は履歴として残し、version 1.2の編集用画像対には適用しない。現行契約は`FLEX-DIM-005`とする。

### FLEX-DIM-003 既存出力と保存寸法（version 1.1、置換済み）

version 1.1では既存出力を原画像・入力三値画像から成る画像対へ追加して寸法照合した。この識別子は
履歴として残し、version 1.2の編集用画像対には適用しない。現行契約は`FLEX-DIM-005`と
`FLEX-SAVE-001`とする。

### FLEX-DIM-005 選択ラベル源の寸法とOrientation

編集用画像対では、表示方向を反映した原画像と、選択ラベル源の復号後の幅および高さが完全に一致
しなければならない。異なる場合は双方の実寸とpathを示して開かない。`OUTPUT`選択時は入力三値画像の
寸法を調べない。`INPUT`選択時は入力三値画像を選択ラベル源として厳格に照合する。

原画像は`FLEX-ORIG-001`どおりEXIF Orientationを表示方向へ反映した寸法を使う。入力または出力の
ラベルPNGは、Orientationがないか値1の場合だけ受理し、値2〜8は自動転置せず拒否する。ラベルJPEGは
`FLEX-JPEG-002`どおり値2〜8を拒否する。原画像のOrientation反映以外の自動拡縮、切抜き、余白追加、
回転、位置合わせを行わない。

### FLEX-DIM-004 下端保護領域

画像高さを `H` とする。`H>100` の場合は行 `H-100` から `H-1` までの末尾100行を下端保護領域と
する。`H<=100` の場合は保護領域を設けない。保護領域がある場合は、従来どおり全画素の入力検査後に
ラベル0へ正規化し、全編集算法、小領域解析、保存用複製から除外または再正規化する。

## 8. 保存時の根拠

### FLEX-SAVE-001 選択源に従う保存基準

保存前の外部変更検査は、原画像、選択ラベル源、および保存対象となる出力pathのsnapshotに限る。
`OUTPUT`から再開した場合は原画像と出力を検査し、選択されていない入力三値画像を保存基準に含めない。
そのため、読込後に未使用の入力三値画像が変更、破損、削除されても、それだけを理由に保存を止めたり、
入力変更確認を表示したりしない。

`INPUT`から開始した場合は原画像と入力三値画像を厳格な保存基準に含め、出力pathの存在・内容変更も
既存の置換確認と外部変更確認で扱う。fallback許可、入力変更後のsnapshot保存許可、既存出力の置換
許可、外部出力変更の上書き許可を一つの許可へまとめない。

## 9. 非目的

本追補は、画像内容による自動対応、EXIF撮影時刻対応、手動の行入替え、再帰的フォルダ探索、画像の
自動変形（原画像のOrientation表示反映を除く）、PNG入力の自動三値化、JPEG入力の自動保存、入力
ファイルの書換えを追加しない。

自然順確認は対応関係を利用者が目視受理するための判断門であり、画像内容が正しい組であることを
ソフトウェアが証明する機能ではない。JPEG最近傍三値化も、圧縮前ラベルを復元できるという保証では
ない。

| FLEX-AT-008 | 既存出力の寸法不一致を拒否し、新規保存および正常上書き後のPNG寸法が画像対と一致する。 |
| FLEX-AT-009 | `H=101`以上では末尾100行だけを保護し、`H=100`以下では保護行を設けず、読込・全編集算法・解析・保存が同じ境界を用いる。 |
| FLEX-AT-010 | 復号可能なRGBA、索引色、16-bit、CMYK、Orientation付き、壊れたICC付き原画像を表示用RGBへ正規化して受理し、Orientation反映後に寸法照合する。復号不能画像は拒否し、入力内容hashを変更しない。 |
| FLEX-AT-011 | version 1.1の履歴受入条件。既存出力の自動優先と入力JPEG確認抑止だけを検査した。`FLEX-AT-012`〜`016`に置換し、この証拠だけからversion 1.2契約の充足を導出しない。 |
| FLEX-AT-012 | 原・入力群の非零同数で対応計画を作り直す。計画成立後に正常な出力を選ぶと編集用画像対が原画像＋出力になり、入力三値の復号・形式・色・寸法・Orientation・内容指紋検査を一切呼ばない。出力がない時は原画像＋入力となり、入力の厳格検査を維持する。 |
| FLEX-AT-013 | 原画像はEXIF Orientation反映後の表示寸法、選択ラベル源は復号後寸法を使って幅・高さを完全照合する。ラベルPNGはOrientationなし／1だけを受理し、2〜8を拒否する。 |
| FLEX-AT-014 | preflightと前後移動は不正候補をmodalなしで飛ばし、直接指定した行だけ対象と理由を一回表示する。出力由来の失敗と分類不能例外を恒久的な画像対cacheへ入れない。 |
| FLEX-AT-015 | 不正出力から入力版へのfallback許可を出力snapshotへ結び付け、同じsnapshotでは再確認しない。出力が変化した時だけ再検査し、正常なら確認なしで`OUTPUT`を採用し、なお不正なら新しいsnapshotについて再確認する。 |
| FLEX-AT-016 | 出力から再開した保存は原画像と出力だけを外部変更検査し、未使用入力の変更・破損・削除で阻害されない。入力から開始した保存は入力の厳格な変更検査を維持する。 |

`FLEX-AT-007`、`008`、`010`はversion 1.1までに得た入力源・出力寸法・原画像正規化の部分証拠として
保持する。選択源境界を含む現行受入は`FLEX-AT-012`〜`016`で判定する。

## 11. 証拠とWindows判断門

要求追跡表で、実装、局所自動試験、Windows実機確認を別状態として記録する。少なくとも、件数門、
両対応方式、毎回確認、JPEG警告各分岐、ICC変換、三値化tie、入力hash不変、複数寸法、対と既存出力の
寸法不一致、`H=100/101`境界を自動検証する。

原画像の表示正規化、選択ラベル源だけとのOrientation反映後寸法照合、ラベルPNGのOrientation拒否、
復号失敗、入力不変、既存出力の無対話優先、未使用入力を開かないこと、fallback snapshot、通知回数、
失敗cacheの無効化、選択源別の保存基準も自動検証する。version 1.1までの試験成功から、これらの
version 1.2追加条件の成功を導出しない。

Windows配布候補では、日本語・互換文字・数字列を含む実ファイル名の整列表示、全表の可読性、JPEG
警告、対象業務画像の読込・保存、入力不変を人間が確認する。局所自動試験や監査は最終受理を代行しない。
