## 0. 読者と用途

本追補は実装者と試験者が、入力画像群の対応付け、三値JPEGの取込、画像寸法、下端保護を
同じ契約で照合するための規範文書である。利用者向けの短い操作手順はREADMEに置く。
本書の `FLEX-*` は実装が満たすべき状態を表し、現在の実装完了やWindows配布受理を単独では
主張しない。現在状態と証拠は要求追跡表の `FLEX-AT-*` を参照する。

## 1. 適用関係

本追補は開発仕様書 v1.5 のうち、次の事項だけを上書きする。

- 原画像と三値画像の対応付け方法
- 対応付け前に必要な画像群の件数条件
- 入力三値画像として受理するJPEGと、その三値化規則
- `2048×1536`固定の読込・編集・保存寸法条件
- 固定座標 `y=1436..1535` としていた下端保護領域

同じ事項で両者が衝突する場合は本追補を優先し、それ以外はv1.5を引き続き基線とする。
マウス入力割当については `mouse-input-bindings-addendum.md` が優先する。追補同士の適用範囲は
交わらない。

v1.5のHTMLと基線SHA-256は変更しない。本追補由来の要求と受入条件には `FLEX-` 接頭辞を
付け、v1.5本文の要求ID、`AT-001`〜`AT-079`、`PTR-*`と混同しない。

## 2. 用語と入力群境界

### FLEX-DATA-001 対応形式画像

入力フォルダ直下にある通常ファイルのうち、次の拡張子を大文字小文字を区別せず対応形式画像と
する。下位フォルダは探索しない。

- 原画像: `.png`、`.jpg`、`.jpeg`、`.bmp`、`.tif`、`.tiff`
- 三値画像: `.png`、`.jpg`、`.jpeg`

拡張子が対応外のファイルは候補数へ含めず、理由付き対象外項目として表示する。対応拡張子を持つ
ファイルは、ファイル名が厳格対応キーに適合するか、復号後の画像内容が正しいかにかかわらず、
候補数へ含める。ファイル名と画像内容の検査は件数検査と別の段階で行う。

### FLEX-DATA-002 画像群の件数門

原画像群と三値画像群は、対応形式画像をそれぞれ1件以上含み、その件数が同一でなければならない。
片方が0件、または件数が異なる場合は画像対を一件も導入せず、両群の候補数を示して読込を止める。
短い側に合わせた切捨て、余剰ファイルの黙示無視、別方式への自動fallbackを行わない。

この件数一致は「正しく対応した」ことの証明ではない。厳格対応ではキー検査、自然順対応では
全対応表に対する利用者確認を別に要求する。

## 3. 対応付け方式

### FLEX-PAIR-001 厳格対応

既定方式は「仕様キーで厳格対応」とする。方式を保存していても、初回状態および不明・破損値からの
復旧先は厳格対応とする。自然順対応へ黙って切り替えない。

厳格対応ではv1.5のキー規則を維持する。

- 原画像の幹名先頭 `①` / `②` を群 `001` / `002` とする。
- 三値画像の幹名先頭 `001` / `002` を同名の群とする。
- 幹名をUnicode NFCへ正規化し、末尾27 Unicodeコードポイントを比較する。
- 群と末尾が大文字小文字を含め完全一致した一対だけを対応させる。
- 想定外の先頭、短い幹名、重複、相手欠落、出力名衝突は理由付き対象外とする。

件数門を通った後でも、厳格キーに適合しないファイルを順番だけで補完してはならない。

### FLEX-PAIR-002 自然順対応

「ファイル名の自然順で対応」は利用者が明示選択した場合だけ使う。原画像群と三値画像群を別々に
整列し、同じ一覧位置のファイルを一対とする。厳格対応の失敗を契機とした自動fallbackにはしない。

整列専用の比較値は拡張子を含むファイル名をUnicode NFKCへ正規化し、十進数字の連続部分を数値、
その他を大文字小文字非依存の文字列として比較する。同順位はNFKC後のファイル名を大文字小文字
非依存で比較し、さらに絶対pathで決定的に解決する。NFKCは整列だけに使い、ファイルまたは厳格
対応キーの同一性を変更しない。

出力名は各三値画像の幹名に `.png` を付けた物とする。Windowsで同じ出力名になる衝突が一件でも
あれば、自然順の対応全体を導入しない。

### FLEX-PAIR-003 全対応表の毎回確認

自然順対応を導入する前に、番号、原画像名、三値画像名、出力PNG名を全件並べた対応表を表示する。
利用者が「この対応で読み込む」を明示した場合だけ導入する。中止を既定選択とし、中止時は現在の
画像集合、編集内容、出力先を変更しない。

確認結果は永続的な許可として再利用しない。フォルダ選択、保存済みフォルダの起動時再走査、手動
再走査など、自然順の対応計画を作るたびに全表を再表示し、改めて確認を得る。

## 4. 三値JPEGの取込

### FLEX-JPEG-001 警告と取消既定

三値画像がJPEGなら、その画像を開く直前に不可逆な三値化を行う旨、変換規則、入力不変、保存先が
PNGであることを警告する。「中止」を既定およびEscape時の選択とし、利用者が「三値化して開く」を
明示した場合だけ復号・三値化する。許可は画像一件ごとに得て、後続JPEGへ流用しない。

### FLEX-JPEG-002 受理するJPEG

実形式がJPEGで、復号後が8-bit RGBまたは8-bitグレースケールであり、正の幅と高さを持つ画像だけを
受理する。透明情報、CMYK等の別色模型、EXIF Orientation 2〜8、復号不能画像は自動補正せず拒否する。

埋込ICC色特性がある場合は、メモリ上でICC変換を行ってsRGBへ変換した後に三値化する。ICCがない
場合は復号したRGB値をsRGB入力値として三値化へ渡す。不正なICC色特性を黙って無視してはならない。

### FLEX-JPEG-003 決定的三値化

三値化の保存色 `SAVE_RGB` とラベル順は次に固定する。

| ラベル | 保存色 |
| --- | --- |
| 0 | `(0, 0, 0)` |
| 1 | `(128, 128, 128)` |
| 2 | `(255, 255, 255)` |

sRGB画素 `p=(R,G,B)` と保存色 `c` の距離を
`d(p,c)=(R-cR)^2+(G-cG)^2+(B-cB)^2` とし、距離が最小のラベルへ一画素ずつ割り当てる。
同距離なら数値が小さいラベルを採る。乱数、dither、周辺画素参照、画像ごとの自動閾値を使わない。

### FLEX-JPEG-004 入力不変と保存

JPEGの復号、ICC変換、三値化、下端正規化はメモリ上だけで行い、入力JPEGを改名、移動、上書き、
PNG化しない。三値化後は未保存状態とし、既存の明示保存操作を行った場合だけ出力フォルダへ
8-bit RGB、アルファなし、三保存色だけのPNGとして保存する。

厳格な三色PNG入力は従来どおり色を再量子化しない。PNGに許容外の色があればJPEG規則へ
fallbackせず拒否する。

## 5. 寸法と下端保護

### FLEX-DIM-001 任意の正寸法

アプリケーションの入力寸法を `2048×1536` に固定しない。幅と高さがともに正で、各形式の復号条件を
満たす画像を候補にできる。`2048×1536`は想定用途および性能測定に使う代表実寸であって、読込要件
ではない。

### FLEX-DIM-002 画像対の同寸

一対を編集用に開く時、復号後の原画像と入力三値画像の幅および高さが完全に一致しなければならない。
異なる場合は双方の実寸とpathを示してその対を開かない。自動拡縮、切抜き、余白追加、回転、位置
合わせを行わない。

### FLEX-DIM-003 既存出力と保存寸法

既存出力を編集元として開く場合、その幅と高さも当該画像対と完全に一致しなければならない。不一致の
既存出力は編集元として拒否する。既存の入力版fallbackを使う場合も、利用者が別途明示選択する。
新規または上書き保存するPNGの寸法は、開いている画像対の実寸と同一とする。

### FLEX-DIM-004 下端保護領域

画像高さを `H` とする。`H>100` の場合は行 `H-100` から `H-1` までの末尾100行を下端保護領域と
する。`H<=100` の場合は保護領域を設けない。保護領域がある場合は、従来どおり全画素の入力検査後に
ラベル0へ正規化し、全編集算法、小領域解析、保存用複製から除外または再正規化する。

## 6. 非目的

本追補は、画像内容による自動対応、EXIF撮影時刻対応、手動の行入替え、再帰的フォルダ探索、画像の
自動変形、PNG入力の自動三値化、JPEG入力の自動保存、入力ファイルの書換えを追加しない。

自然順確認は対応関係を利用者が目視受理するための判断門であり、画像内容が正しい組であることを
ソフトウェアが証明する機能ではない。JPEG最近傍三値化も、圧縮前ラベルを復元できるという保証では
ない。

## 7. 受入条件

| 受入ID | 条件 |
| --- | --- |
| FLEX-AT-001 | 両群が非零同数の時だけ対応計画を作る。0件または件数不一致では0組となり、両候補数を表示する。 |
| FLEX-AT-002 | 厳格対応が既定で、従来キーの一致だけを採用し、不正名を自然順で黙って補完しない。 |
| FLEX-AT-003 | 自然順を明示選択すると別々の決定的整列から全対応表を示し、取消時は現状態不変、再走査時は再確認となる。 |
| FLEX-AT-004 | 三値JPEGごとに取消既定の警告を示し、取消時は現在の画像、編集内容、入力、出力を変更しない。 |
| FLEX-AT-005 | ICC後sRGBの既知画素を三保存色の二乗距離最小へ割り当て、距離同値で小ラベルを選ぶ。乱数なしで同じ入力から同じ配列を得る。 |
| FLEX-AT-006 | JPEG取込前後で入力内容hashが不変で、取込直後は未保存となり、明示保存後の出力が同寸の8-bit RGB三色PNGになる。 |
| FLEX-AT-007 | 異なる複数の正寸法の対を開け、原画像と入力三値画像の寸法不一致は双方の実寸付きで拒否し、resizeしない。 |
| FLEX-AT-008 | 既存出力の寸法不一致を拒否し、新規保存および正常上書き後のPNG寸法が画像対と一致する。 |
| FLEX-AT-009 | `H=101`以上では末尾100行だけを保護し、`H=100`以下では保護行を設けず、読込・全編集算法・解析・保存が同じ境界を用いる。 |

## 8. 証拠とWindows判断門

要求追跡表で、実装、局所自動試験、Windows実機確認を別状態として記録する。少なくとも、件数門、
両対応方式、毎回確認、JPEG警告各分岐、ICC変換、三値化tie、入力hash不変、複数寸法、対と既存出力の
寸法不一致、`H=100/101`境界を自動検証する。

Windows配布候補では、日本語・互換文字・数字列を含む実ファイル名の整列表示、全表の可読性、JPEG
警告、対象業務画像の読込・保存、入力不変を人間が確認する。局所自動試験や監査は最終受理を代行しない。
