1. 目的・適用範囲

1.1 製品目的

同一対象に対応する原画像と三値画像を画素座標が一致した状態で重畳表示し、利用者が原画像を参照しながら三値画像のみを修正し、修正版を別フォルダへ保存できるようにする。

OBJ-001
誤りの最終判断は利用者が目視で行う。ツールは正解画像を推論せず、比較・編集・規則処理を支援する。
OBJ-002
原画像は常に読取専用とし、編集・Undo・Redo・保存の対象にしない。
OBJ-003
入力三値画像を上書きせず、編集済み画像を専用出力フォルダへ明示保存する。

1.2 初期版で扱う範囲

  • 複数の画像対の読込、対応付け、自然順整列、前後移動。
  • 原画像と三値画像の重畳比較、疑似色表示、原画像不透明度変更。
  • 筆・塗り潰しによる三値画像編集。
  • Undo・Redo。
  • 二種類の自動境界生成。
  • 50画素以下の独立成分の強調表示。
  • 別フォルダへの検証付き保存。

2. 用語と画素規則

用語定義
原画像比較対象となる無加工の画像。ファイル名は原則として ① または ② で始まる。
三値画像#000000、#808080、#FFFFFF の三値だけで構成される編集対象画像。ファイル名は 001 または 002 で始まる。
編集済み画像出力フォルダに保存された三値画像の修正版。
無黒 #000000。内部ラベル値 0。
有灰 #808080。内部ラベル値 1。
境界白 #FFFFFF。内部ラベル値 2。
四近傍対象画素の上・下・左・右。斜めは含まない。
八近傍四近傍に斜め四方向を加えた八方向。
自然順整列数字列を数値として比較し、1, 2, 10 の順に並べる方式。
規則の使い分け：塗り潰しと境界生成は誤変更を抑えるため四近傍、小領域検出は斜めに連なる塊を見逃さないため八近傍を使う。美観のために近傍規則を統一してはならない。

3. 入出力データ

3.1 共通条件

DAT-001
原画像・三値画像はともに 2048 × 1536ピクセルであること。
DAT-002
画像対は回転、反転、切抜き、拡縮を含めて座標系が完全に一致していること。
DAT-003
寸法不一致時に自動拡縮や位置合わせを行わず、その画像対を編集対象外とする。

3.2 原画像

  • 読込形式：PNG、JPEG、BMP、TIFF。
  • 表示時に復号・画面拡縮は行うが、画素値の補正、輪郭強調、平滑化、保存処理は行わない。
  • EXIF Orientationがある場合は表示方向へ正規化した後に寸法検査する。原ファイル自体は変更しない。

3.3 三値画像・出力画像

  • 入力形式：8-bit PNG。RGBまたはグレースケールを許容する。
  • グレースケール値は 0 → 無、128 → 有、255 → 境界 と解釈する。
  • RGB値は (0,0,0)、(128,128,128)、(255,255,255) のみ許容する。
  • アルファチャンネル、16-bit、索引色、その他の色を含む入力は拒否する。
  • 内部表現は uint8 の二次元ラベル配列 0/1/2 とする。
  • 出力形式は2048 × 1536、8-bit RGB PNG、アルファなし、三色のみとする。

4. ファイル対応付け・順序

4.1 フォルダ指定

利用者は次の三フォルダを個別に指定する。初期版は下位フォルダを探索しない。

  1. 原画像フォルダ
  2. 三値画像フォルダ
  3. 編集済み画像出力フォルダ

4.2 対応キー

原画像先頭三値画像先頭正規化群番号

②002002

拡張子を除いたファイル名を「幹名」とする。一組の対応キーは次で定義する。

pair_key = (正規化群番号, 幹名の末尾27文字)
PAIR-001
群番号と末尾27文字の双方が一致した原画像・三値画像だけを一組として採用する。
PAIR-002

4.3 整列

対応付け後の画像対は、三値画像の幹名を基準に、大文字小文字を区別しない自然順で整列する。同順位時は完全パスを補助キーとする。

4.4 出力名

出力ファイル名は三値画像の幹名を継承し、拡張子を .png とする。出力フォルダ直下へ保存する。

5.1 現在画像の状態

状態意味
未読込有効な画像対が選択されていない。

編集済み・未保存現在配列が最後の保存時点または読込時点と異なる。

5.2 未保存状態からの移動・終了

前画像、次画像、一覧選択、フォルダ再読込、アプリ終了のいずれでも、未保存変更がある場合は次を提示する。

選択肢動作

変更を破棄して続行未保存変更と現在画像のUndo・Redo履歴を破棄して続行する。
中止遷移・終了を行わない。

5.3 移動先に編集済み画像がある場合

選択肢動作
編集済み画像から続ける出力画像を編集元として開く。以後の保存は同じ出力へ置換保存する。
入力三値画像から始める入力版を編集元として開く。既存出力は変更しない。後に保存する際、既存出力の上書きを再確認する。
中止移動しない。

7. 表示仕様

7.1 レイヤ構成

  1. キャンバス背景：画像外余白を示す中立色の表示領域。画像データには含めない。
  2. 下層：三値画像の表示像。
  3. 上層：原画像。
  4. 最前面：画像外枠、筆範囲、画素格子、小領域強調等の保存対象外オーバーレイ。

原画像と三値画像は個別に表示・非表示を切り替えられる。原画像の不透明度は0～100％、初期値50％とする。

7.2 GIMP互換比較モード

解釈固定：GIMPでは最下層へ設定した通常以外のレイヤーモードは表示結果へ作用しない。したがって、「三値画像＝比較（暗）」という設定名は互換表示の計算には寄与せず、三値画像を通常の不透明基底、原画像を上層の「比較（明）」として実装する。

三値表示画素を T、原画像画素を O、原画像不透明度を α とする。各値はsRGB 8-bit成分を0～1へ正規化し、RGB成分ごとに次を計算する。

M = max(T, O)
Display = (1 - α) × T + α × M
  • α = 0 では三値画像だけを表示する。
  • α = 1 では max(T, O) を表示する。
  • 色管理やGIMP内部の丸め差までの完全一致は対象外とし、8-bit出力の差が各成分±1以内なら互換とみなす。
  • 規範は本節の数式であり、将来のGIMP既定値変更には追随しない。

7.3 疑似色モード

三値の保存値は変更せず、表示時のみ高色差の疑似色へ写像できる。初期配色は次とし、設定画面で変更可能とする。

ラベル保存色初期疑似色
無#000000#204060（濃青）
有#808080#FF3B7A（赤紫）
境界#FFFFFF#FFE600（黄）

疑似色モードでは、色の意味を保つため原画像を通常のアルファ合成で重ねる。疑似色、格子、警告表示は保存画像へ含めない。

7.4 拡大・縮小・表示範囲移動

VIEW-001
マウスホイールによる拡大縮小は、操作開始時のマウスポインタ直下にある画像座標を可能な限り固定する。
VIEW-002
表示倍率は5％～6400％。100％表示と全体表示を用意する。
VIEW-003
中ボタンドラッグまたはSpace＋左ドラッグで表示範囲を移動する。
VIEW-004
画像切替時は倍率と表示中心座標を維持する。ただし全体表示中は切替先も全体表示とする。
VIEW-005
三値画像は最近傍補間で表示する。原画像は縮小時に高品質補間、100％以上では画素位置を保つ補間を用いる。いずれも元ファイルを変更しない。
VIEW-006
表示範囲移動は画像矩形の内側へ制限せず、画像外の仮想余白まで許可する。画像の各辺および各隅をキャンバス表示領域の中央まで移動できること。
VIEW-007
ツール欄等を除いた実際のキャンバス表示領域を幅 Vw・高さ Vh、現在倍率での画像表示寸法を幅 Iw・高さ Ih、画像左上の表示座標を (x, y) としたとき、パン可能範囲を原則として Vw/2 - Iw ≤ x ≤ Vw/2、Vh/2 - Ih ≤ y ≤ Vh/2 とする。これにより、画像を完全に見失わせず、任意の端部を中央付近で確認・編集できるようにする。
VIEW-008
画像外余白は画像と判別できる中立色または市松模様で表示し、画像境界には保存対象外の明瞭な外枠を表示する。画像外は編集対象ではなく、筆・塗り潰し・画素参照は作用しない。画像内から画像外へ跨ぐ筆描画は画像矩形で切り詰める。
VIEW-009
全体表示では画像全体を中央配置し、キャンバス寸法が許す限り上下左右に各32論理画素以上の余白を確保する。余白確保と画像全体表示が両立しない場合は、画像全体を欠けずに表示することを優先する。
画像外余白の意図：画像端をウィンドウ端へ貼り付けず、端部や四隅をキャンバス中央付近へ持ってきて確認・描画できるようにするための表示上の余裕である。余白は保存画像の画素追加、画像寸法変更、座標系変更を意味しない。

7.5 画素格子

一つの画像画素が実画面上で8画素以上の幅を占めるとき、自動的に画素格子を表示する。利用者は自動表示を無効化できる。

  • 格子線は1実画面画素、半透明、保存対象外。
  • Windowsの表示倍率を考慮し、Qtの論理座標ではなく機器画素比を反映した表示幅で判定する。

7.6 座標精度

ズーム、DPI倍率、スクロール量にかかわらず、画面座標から画像座標への変換誤差によって隣接画素を編集してはならない。筆ポインタは実際に変更される画素範囲を示す。

8. 編集機能

8.1 共通

  • 編集対象は三値ラベル配列だけとする。
  • 選択色は「無」「有」「境界」の三つだけ。
  • 半透明、ぼかし、アンチエイリアス、中間色を生成しない。
  • 表示用疑似色を編集値として書き込まない。

8.2 筆

筆形状円形、正方形
筆径1～512画像画素、初期値5
操作左押下から解放まで描画。ドラッグ点間を補間し、高速移動でも線を途切れさせない。
画像外画像内部分だけを変更する。画像外は無視する。
Undo単位一回の押下から解放までを一操作とする。

低倍率で誤編集を防ぐため、画面上の筆径が4実画面画素以上の場合だけ描画を許可する。

editable = brush_diameter_in_image_pixels × display_scale × device_pixel_ratio ≥ 4

条件未満では筆ポインタを禁止表示にし、画像を書き換えず、状態欄へ理由を表示する。

8.3 塗り潰し

  • クリック地点と同じ内部ラベル値を持ち、上下左右で連続する領域を選択色へ置換する。
  • 四近傍連結を使用し、斜め方向だけで接する同色領域は含めない。
  • 許容差は設けず、ラベル値が完全一致する画素だけを対象とする。
  • 対象色と選択色が同じ場合は変更せず、履歴も追加しない。
  • 一回の塗り潰しを一つのUndo単位とする。
  • 低倍率筆径制限の対象外とする。

8.4 初期版で搭載しない編集機能

  • 直線描画
  • 矩形選択
  • スポイト
  • コピー・貼り付け
  • 前後画像からの複製
  • 選択範囲だけの自動境界生成

9. Undo・Redo

HIST-001
筆、塗り潰し、境界生成をUndo・Redo対象とする。
HIST-002
表示倍率、表示位置、不透明度、疑似色、格子、小領域表示の変更は履歴へ入れない。
HIST-003
Undo後に新しい編集を行った場合、その時点より先のRedo履歴を破棄する。
HIST-004
保存時点を履歴位置として記録し、保存時点からUndoまたはRedoで離れた場合は未保存状態とする。
HIST-005
履歴は現在画像の編集セッションだけ保持し、画像を離れた時点で破棄する。再訪時に過去セッションのUndoは復元しない。

履歴上限は「200操作」または「512MiB」の先に到達した方とし、超過時は古い履歴から破棄して状態欄へ通知する。

10. 自動境界生成

10.1 共通仕様

  • 現在画像全体を対象とする。
  • 四近傍だけを用いる。斜め接触だけでは太さ1の境界を生成しない。
  • 境界太さは1～64画素、初期値1。
  • 処理開始時点のラベル配列を基準に対象を一括決定する。
  • 一回の実行全体を一つのUndo単位とし、Redo可能とする。
  • 変更画素が0の場合は履歴へ追加しない。
  • 処理後に小領域検出結果を再計算する。
  • 原画像は変更しない。

画面には「生成方向」「太さ」「境界を生成」ボタンを置き、Ctrl+Shift+B で選択中モードを実行する。

10.2 モードA：無側へ生成

既存方式「有」と「無」が直接接し、間に「境界」がない箇所について、無側の画素を境界へ変更する。

規則

  1. 処理開始時点で、四近傍に「有」がある「無」画素を接触種 S0 とする。
  2. 太さ1では S0 を「境界」へ変更する。
  3. 太さNでは、S0 から「無」画素だけを通って四近傍距離 0～N-1 で到達できる「無」画素を「境界」へ変更する。
  4. 既存の「境界」は通過元にも書換対象にもせず、既存境界が「有」と「無」の間にある箇所では新たに生成しない。
  5. 「有」と既存「境界」は変更しない。
太さ1
処理前: 無 有 有
処理後: 境 有 有

既存境界あり
処理前: 無 境 有
処理後: 無 境 有  （変更なし）
意味：不足している境界を「無」側へ張り出させる。既存境界を越えて追加膨張しない。

10.3 モードB：非無側へ生成

追加方式「無」と「有または境界」の境界について、有・境界側を一定幅の境界へ変更する。黒側は維持する。

規則

  1. 「無」を基準集合とする。
  2. 各非無画素について、「無」から非無画素だけを通る四近傍最短距離を求める。
  3. 距離が1～Nである「有」または「境界」画素を「境界」へ設定する。
  4. 既存境界は最終幅へ数える。したがって同じ太さで繰り返しても際限なく太くならない。
  5. 「無」は変更しない。画像外部を「無」とみなさない。
太さ1
処理前: 無 有 有
処理後: 無 境 有

既存境界あり・太さ1
処理前: 無 境 有
処理後: 無 境 有

既存境界あり・太さ2
処理前: 無 境 有 有
処理後: 無 境 境 有
注意：幅の狭い「有」領域は、このモードによって全体が境界へ変わり得る。これは仕様上の正常動作であり、Undoで戻せる。

11. 50画素以下の独立成分表示

COMP-001
「有」と「境界」を色ごとに分離し、それぞれ八近傍連結成分を求める。「有」と「境界」を同一成分として結合しない。
COMP-002
面積が1～50画素の成分を対象とする。50画素ちょうどを含む。「無」は対象外。
COMP-003
対象成分を画面上だけで強調し、三値配列や保存画像を変更しない。
COMP-004
強調表示は切替可能とし、検出成分数を状態欄へ表示する。

11.1 表示方法

  • 対象画素へ半透明の警告色を重畳する。
  • 成分の外接矩形を2実画面画素の警告線で表示する。
  • 警告色は疑似色と区別できるよう、白黒交互または高彩度の縞表示を用いる。

11.2 再計算契機

  • 画像読込後
  • 筆描画終了後
  • 塗り潰し完了後
  • Undo・Redo後
  • 境界生成後
  • 表示をOFFからONへ切り替えた時

解析を別処理単位で実行する場合、画像改訂番号を照合し、古い解析結果を新しい画像状態や別画像へ反映しない。

12. 保存・既存出力の扱い

12.1 明示保存

SAVE-001
正式保存は保存ボタンまたは Ctrl+S でのみ行う。画像移動時の「保存して続行」も同じ保存処理を呼ぶ。
SAVE-002
入力原画像・入力三値画像を上書きしない。
SAVE-003
疑似色、原画像、格子、筆ポインタ、小領域警告を保存しない。内部ラベル配列から直接PNGを生成する。

12.2 原子的保存

  1. 出力フォルダ内へ一時ファイルを書き出す。
  2. 一時ファイルを再読込する。
  3. 寸法、8-bit RGB、アルファなし、三色のみであることを検証する。
  4. 検証成功後、OSの置換操作で正式ファイルへ反映する。
  5. 失敗時は既存出力へ触れず、一時ファイルを削除し、未保存状態を維持する。

12.3 既存出力

  • 編集済み画像を編集元として開いた場合、通常の保存で同じ出力を置換する。
  • 既存出力を無視して入力三値画像から開いた場合、最初の保存時に既存出力の上書きを確認する。
  • 読込後に外部アプリが出力ファイルを変更した場合、内容ハッシュまたは更新時刻で競合を検出し、無言で上書きしない。

12.4 異常終了

初期版では未保存編集の自動復元を必須としない。異常終了時に未保存変更が失われ得ることを利用者向け説明へ明記する。正式出力と入力は原子的保存により保護する。

13.4 保存・終了

事象処理

未保存で移動・終了保存、破棄、中止を提示する。
保存中に終了要求保存結果が確定するまで終了を保留する。
最初で「前へ」／最後で「次へ」操作を無効化し、自動周回しない。
異常終了未保存変更は失われ得る。入力・既存出力は破壊しない。

14. 非機能要件

14.1 動作環境

  • Windows 10 / 11 64-bit
  • Python 3.11.x
  • オフラインで全機能を利用可能
  • 日本語・丸数字を含むUnicodeパスに対応
  • Windows表示倍率100～200％で座標精度を維持

14.2 データ完全性

  • 原画像と入力三値画像へ書込みを行わない。
  • 保存前後に三色制約と寸法を検証する。
  • 表示画像を保存元に用いない。
  • 例外発生時も正式出力を半端な状態へ置換しない。

14.3 性能目標

以下はWindows 11、4物理コア以上、16GB RAM、SSDの一般的な業務PCを基準とする目標値。外部仕様を損なわない範囲で調整可能。

操作目標
画像対読込・初期表示2秒以内
筆追従入力から画面反映まで50ms以内を目標
塗り潰し・境界生成・小領域解析通常3秒以内。処理中もウィンドウを応答不能にしない。
保存3秒以内を目標
常用メモリ現在画像・表示・履歴を含め1GiB未満を目標

17. 推奨実装構成 参考設計

領域推奨
GUIPySide6。画像キャンバスはQGraphicsViewまたは専用QWidget。
画像復号Pillow。原画像のEXIF Orientationを表示時のみ反映。
三値内部表現NumPy uint8[1536, 2048]、値0/1/2。
画素処理NumPy＋OpenCVまたはSciPy。連結成分・距離・膨張は配列演算で実施。
Undo変更矩形または変更画素のbefore/after差分を命令単位で保持。
表示原画像、ラベル色像、警告オーバーレイを分離し、表示変更でラベル配列を再生成しない。
長時間処理QThreadPool等で小領域解析を実行し、画像改訂番号で古い結果を破棄。
保存一時PNG作成、再検査、os.replace による置換。
設定QSettings。直前フォルダ、疑似色、筆径、表示設定のみ保存し、未保存画像内容は保存しない。
設計上の要点：「保存データ」「表示像」「操作オーバーレイ」を分離する。画面をそのまま保存する実装は、疑似色や格子まで成果物へ混入させるので禁止する。

18. 推奨開発順序

  1. データ層：ファイル対応付け、入力検査、ラベル配列変換、原子的保存。
  2. 閲覧層：画像一覧、重畳表示、GIMP互換合成、疑似色、不透明度、ズーム、パン、格子。
  3. 基本編集：三色選択、円・正方形筆、塗り潰し、低倍率制限。
  4. 履歴：Undo・Redo、保存位置、未保存判定。
  5. 規則処理：無側境界、非無側境界、太さ、全体Undo。
  6. 検査支援：小領域解析、警告オーバーレイ、改訂番号制御。
  7. 遷移・異常系：未保存確認、既存出力選択、外部変更、保存失敗。
  8. 受入試験・配布：AT-001～033、自動試験、Windows実機、高DPI確認、配布手順。

19. 初期版の対象外

  • 画像の自動位置合わせ、回転、拡縮、切抜き。
  • 原画像から正解三値画像を推論する機械学習。
  • 四値以上のラベル、任意色、半透明ラベル。
  • 下位フォルダの再帰探索。
  • 複数画像を未保存のまま同時保持するタブ編集。
  • 選択範囲、直線、スポイト、コピー・貼り付け、前後画像複製。
  • 選択範囲だけの境界生成。
  • 異常終了後の未保存編集自動復元。
  • macOS・Linux対応、Web版、複数人同時編集。
