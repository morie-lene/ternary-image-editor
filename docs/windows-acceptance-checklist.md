# Windows最終受入チェックリスト

ローカル自動試験の成功と、Windows向け成果物の最終受理は分ける。各欄には実行日、
応用版、Windows版、表示倍率、モニター、キーボード配列、日本語入力方式、対象PC、
操作した実データ、結果、証拠ファイルを記録する。

## 配布候補

1. Windows上で `scripts/build_windows.ps1` を実行し、表示されたexeの大きさとSHA-256を
   記録する。
2. `dist/TernaryImageEditor/TernaryImageEditor.exe` を開発環境のない別利用者権限で起動する。
   exeだけを抜き出さず、one-folder配布一式を同じ配置に保つ。
3. 包装metadataの応用版が `0.6.0` で、同梱する要求正本がv1.5、柔軟入力・対応付け追補version 1.2、
   マウス入力割当追補version 1.0、表示比較（暗）追補version 1.0であることを記録する。各文書の
   構築時SHA-256がREADMEの固定値と一致することも記録する。
4. 日本語・空白・長いパスを含む三フォルダを指定する。
5. 入力フォルダの内容ハッシュが編集・保存・終了後も不変であることを確認する。
6. 前版が保存した設定を読ませ、既知項目の移行、欠落項目の既定補完、未知項目無視を
   確認する。
7. Explorer上のexe、起動後の主window、タスクバーが同じ採用アイコンを表示し、Qtや
   PyInstallerの既定アイコンへ戻っていないことを確認する。

## アプリケーションアイコン判断門

- [ ] Explorerの大・中・小アイコン表示で、透過外周、黒・灰・白、右下の彩色観察窓が
  欠落または異常変色していない。
- [ ] タスクバーと主windowの16/32px相当で採用図案が表示され、別アイコンへ切り替わらない。
- [ ] 表示倍率100%、125%、150%、200%で輪郭が不自然に欠けず、主windowの再起動後も
  同じアイコンである。
- [ ] 16/32pxで意味が潰れて業務上識別できない場合は受理せず、小寸法光学別稿の要否を
  `decision.windows-application-icon-acceptance`として判断する。

## 基本機能判断門

- [ ] Windows 10で起動、読込、編集、保存、再読込が成功する。
- [ ] Windows 11で起動、読込、編集、保存、再読込が成功する。
- [ ] 高さ100を超える代表画像（例: 2048×1536）の末尾100行に有・境界を含めて開き、
  変更画素数、未保存表示、Undo履歴0件、保存後全黒をAT-034〜037とFLEX-AT-009どおり
  確認する。この実寸例を読込要件として扱わない。
- [ ] 三値画像を隠した間は筆、塗り潰し、境界生成、Undo、Redo、小領域強調、筆範囲が
  停止し、再表示で履歴と未保存内容が戻る（AT-065）。
- [ ] 未変更・出力なしの画像を明示保存すると出力ありへ移り、「確認済み」等の別状態を
  作らない（AT-066、079）。
- [ ] 対象外画像は理由付きエラー一覧に残り、前後移動は有効画像対だけを辿る（AT-076）。
- [ ] 有・境界の小領域件数が別々に表示され、下端保護領域を数えない。

## 柔軟入力・対応付け判断門

- [ ] 原画像群と三値画像群をそれぞれ0件、同数、異数にして走査し、非零同数だけが対応計画へ
  進み、異数では短い側への切捨てや部分読込が起きない（FLEX-AT-001）。
- [ ] 厳格対応が初回既定で、`①/②`対`001/002`と末尾27文字の一致だけを採り、想定外名から
  自然順へ自動fallbackしない（FLEX-AT-002）。
- [ ] 自然順を明示選択し、日本語、`2/10`、全角・丸数字等の互換文字を含む実ファイル名で、
  番号、原画像、三値画像、出力PNGの全行が読み取れる。取消で現在編集が不変となり、起動時再走査と
  手動再走査のたびに再確認される（FLEX-AT-003）。
- [ ] 三値JPEGを開く時、「中止」が既定かつEscapeで選ばれ、取消時に現在編集と入力・出力hashが
  不変である。許可時だけ三値化し、別JPEGへ移動すると改めて警告する（FLEX-AT-004）。
- [ ] ICC有・無の代表JPEGを開き、sRGB上の黒・灰・白への割当、未保存表示、明示保存後の同寸
  8-bit RGB三色PNG、入力JPEGのhash不変を確認する（FLEX-AT-005、006）。
- [ ] `INPUT`を編集元にし、2048×1536以外を含む複数の正寸法で読込・編集・保存できる。原画像の
  表示寸法と入力三値の幅差・高さ差は実寸付きで拒否され、resizeされない（FLEX-AT-007、013）。
- [ ] 高さ1、100、101の画像で、100以下は保護なし、101は末尾100行だけが保護され、筆、塗り、
  境界生成、小領域解析、保存の境界が一致する（FLEX-AT-009）。
- [ ] RGBA、索引色、16-bit、CMYK、Orientation付き、壊れたICC付きの原画像を参照表示でき、
  Orientation反映後の表示寸法で選択ラベル源と照合される。読込・編集・保存後も各原画像のhashが
  不変である（FLEX-AT-010、013）。
- [ ] INPUTとOUTPUTのラベルPNGについて、Orientationなし／1は原寸で受理し、2〜8は自動転置せず
  対象pathと理由を示して拒否する（FLEX-AT-013）。
- [ ] 原・入力群が非零同数の対応計画で正常な既存出力がある対は、選択確認なしで原画像＋出力を開く。
  未使用入力を不正色、寸法違い、壊れたJPEGへ変えても復号・三値化確認・寸法検査を行わない。
  出力がない対では原画像＋入力を開き、入力の厳格検査を維持する（FLEX-AT-012）。
- [ ] preflightと「前へ」「次へ」は不正候補をmodalなしで飛ばし、一覧から同じ不正行を直接開く時は
  対象と理由を一回だけ表示する。出力由来または分類不能の失敗後も、画像対全体が恒久的な対象外に
  ならず再試行できる（FLEX-AT-014）。
- [ ] 不正出力から入力版へのfallbackを一度許可した後、同じ出力snapshotへの再訪では再確認しない。
  出力を正常PNGへ置換すると確認なしでOUTPUTへ戻り、別の不正内容へ変えると改めて確認する
  （FLEX-AT-015）。

## 表示・DPI・geometry判断門

- [ ] 表示倍率100%、125%、150%、200%の各条件でAT-030を実施する。
- [ ] 各辺・四隅を中央へ移動し、AT-031とAT-032を実施する。
- [ ] 全体表示の余白についてAT-033を実施する。
- [ ] 全体表示中のwindow寸法変更で再fitし、手動倍率中は倍率と中心画像座標を維持する
  （AT-073）。
- [ ] 異なるDPIのモニター間を往復し、中心画像座標、格子閾値、4機器画素筆閾値、
  画素選択をAT-074どおり確認する。
- [ ] 最大化状態を含むwindow配置を再起動後に復元する。
- [ ] 前回モニターを外して起動し、保存geometryが画面外なら到達可能な既定位置へ戻る。

## 表示比較（暗）判断門

- [ ] 初回起動では「比較（暗）」が無効で、保存色表示と疑似色表示が従来の比較（明）／通常合成に
  なり、切替を有効から無効へ戻すと同じ画素表示へ戻る（DISP-CMP-001、003）。
- [ ] 比較（暗）を有効にし、原画像不透明度0%、50%、100%で、暗い成分だけが原解像度で反映される。
  100%、125%、150%、200%表示でも合成境界の位置がずれない（DISP-CMP-004）。
- [ ] 保存色と三つの疑似色それぞれで比較（暗）が働き、疑似色設定とラベル値が変わらない
  （DISP-CMP-005）。
- [ ] 三値画像のみ、原画像のみ、双方非表示を切り替え、比較（暗）が隠した層を再出現させない
  （DISP-CMP-006）。
- [ ] 主画面チェック、表示メニュー、任意に割り当てた鍵盤・マウス入力が同じ状態を一回だけ切り替える。
  取消した設定画面の変更は反映せず、適用値は再起動後に復元する（DISP-CMP-002、008）。
- [ ] 同じラベル内容を比較（暗）の無効・有効で各一回保存し、両PNGのSHA-256が一致する。切替で
  未保存表示、Undo・Redo件数、現在画像、入力・既存出力が変わらない（DISP-CMP-007）。

## 操作割当・日本語入力方式判断門

- [ ] 設定画面の操作一覧が基線38件と`view.toggle-darken-comparison`一件の不変ID付き39件であり、
  台帳外操作がない。
- [ ] 全割当を解除しても、主画面の常設設定ボタンとメニューから設定を開ける（AT-049）。
- [ ] 日本語入力方式ON/OFFで `K` と `Ctrl+Shift+K` の取得結果が変わらない。
- [ ] JIS配列と利用対象配列で、保存値がPortableText相当、表示が各配列のNativeText相当
  である（AT-050）。
- [ ] 修飾キー単独、Tab、Shift+Tab、Esc、Alt+F4、Windows/Metaを含む予約入力を
  割り当てない。
- [ ] 入力待機開始前から押されていたキー、KeyUp、自動反復を候補化せず、Esc、別欄選択、
  非活性化で待機を取り消す。
- [ ] 主・副割当、競合時の移動・取消、個別解除、個別既定、全体既定、適用・取消、再起動
  復元をAT-044〜048どおり確認する。
- [ ] 保存を `Ctrl+S` 以外へ変え、旧割当が固定入力として残らない（AT-057）。
- [ ] 選択色の順・逆循環、疑似色との独立、画像移動中の保持、メニュー・ボタン・キーの
  経路一致をAT-051〜056どおり確認する。
- [ ] 刻み操作の自動反復、単発操作の一回限り、割当変更後の一時パン押下・解放を
  AT-058、059、078どおり確認する。

## 筆取引判断門

- [ ] 円形・正方形の奇数径・偶数径で、筆予告と実変更画素が一致する（AT-072）。
- [ ] 描画中はキー、メニュー、toolbar、window操作による他命令が実行も予約もされない。
- [ ] Esc、window非活性化、マウス捕捉喪失で筆跡全体が戻り、正常解放では一履歴単位に
  なる（AT-071）。
- [ ] 描画中にモニターDPIが変わった場合、途中確定せず全取消となる。旧v1.1の
  「DPI変化地点まで確定」は受入基準に使わない。

## マウス入力割当判断門

- [ ] 左・中・右・戻る・進むbuttonとwheel上下を設定画面で捕捉し、`Ctrl`、`Alt`、
  `Shift`を含む保存tokenが [マウス入力割当追補](mouse-input-bindings-addendum.md) の
  正規形になる（PTR-AT-001〜004）。
- [ ] 左・中buttonまたはwheelを割り当てる際に失われる固定操作が表示され、取消時は
  主・副割当と競合元のいずれも変化しない。
- [ ] 主画像Canvas以外の一覧、設定画面、数値欄、button、menu上ではマウス割当が発火せず、
  通常のclickとscrollを奪わない（PTR-AT-005）。
- [ ] 未割当時はwheel拡大・縮小、中button drag自由移動、左button道具操作、Spaceまたは
  GUI一時パン中の左button移動が従来どおり働く。完全一致割当時は、操作が無効でも固定
  操作へfallbackしない（PTR-AT-006）。
- [ ] 戻る・進むbuttonを別々の操作へ割り当て、各buttonの押下・解放が取り違えられない。
- [ ] `HOLD`へ割り当てた中・右・戻る・進むbuttonについて、修飾キーを先に離した場合、
  modal画面を開いた場合、Canvas焦点喪失、window非活性化、マウス捕捉喪失、設定適用の
  各経路で保持状態が残らない（PTR-AT-007、008）。
- [ ] double-clickは実行時に二押下として二回だけ作動し、設定捕捉では一候補だけになる。
- [ ] 通常wheelとprecision touchpadについて、一event単位の起動回数とinertia中の回数を
  記録し、設定捕捉後の残eventが設定画面を意図せずscrollしない。
- [ ] 筆描画中の右・中・戻る・進むbuttonとwheel割当は発火も予約もせず、左button解放で
  一筆が正常確定する（PTR-AT-009）。
- [ ] schema 0または1の実利用設定を退避して読み込み、既存鍵盤割当と明示的未割当を保った
  ままschema 2で保存される（PTR-AT-010、011）。

## 保存・外部変更・多重起動判断門

- [ ] 出力ファイルを他アプリでOSロックした保存失敗時に既存出力が不変で、未保存内容が
  残る。
- [ ] `INPUT`を編集元にした時は、原画像または入力三値画像を読込後に変更し、再読込・読込済み
  snapshot保存・中止が各選択どおり動く。初期選択は中止である。
- [ ] `OUTPUT`から再開した後、未使用入力を変更、破損、削除しても入力変更確認を出さず保存できる。
  原画像または出力を変更した時は既存の外部変更確認を維持する（FLEX-AT-016）。
- [ ] 出力の外部変更・新規出現・削除で、外部版を開く・現在内容で上書き・中止が各選択
  どおり動く。初期選択は中止である。
- [ ] 二つの本アプリプロセスで同じ出力を開き、一方が側車lockを保持中は他方が待たずに
  保存失敗し、既存出力と双方の未保存内容を維持する（AT-070）。
- [ ] 保存中プロセスを強制終了後に再起動し、安定側車lockファイルが残っていてもOS lock
  解放後は保存できる。lockファイルの存在だけを「保存中」と誤判定しない。
- [ ] 一時PNG検証中、置換直前、置換直後の外部変更で、競合が通知され、既存出力または
  回復可能な結果と未保存状態が残る。
- [ ] 同じ側車lock規約に従わない外部writerを、最後の内容照合と `os.replace` 呼出しの間へ
  注入し、結果と回復手順を記録する。この非協調CAS極小窓は本アプリ多重起動ロックとは
  別の残危険である。
- [ ] 非協調writerとの同一出力同時書込を許すなら、運用禁止解除の根拠またはWindows固有の
  条件付き置換相当を別途受理する。
- [ ] 出力先の書込権限喪失時に保存が無効化または失敗通知され、未保存状態が残る。

## 性能判断門

- [ ] 対象用途の代表実寸例である2048×1536の実データを使い、読込2秒、筆反映50ms、長処理3秒、
  保存3秒の目標を反復測定する。この寸法をアプリケーションの受理可能寸法と混同しない。
- [ ] 下端正規化、原解像度合成、離散筆、SHA-256、保存lockを有効にした現行v1.5＋追補経路で測る。
- [ ] 比較（暗）の無効・有効を同じ代表画像で反復し、切替直後の再合成時間と、その後のパン・拡縮時
  間を別々に記録する。
- [ ] 常用メモリが1GiB未満であることを測る。

## 受理記録

この表を埋めた人間が `accept / reject / hold` を明記する。自動試験や監査結果は判断材料で
あり、この受理を代行しない。
